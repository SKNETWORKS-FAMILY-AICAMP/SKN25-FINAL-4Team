## 3. Gemma4 vs EXAONE — 최종 선택 근거

두 자체 호스팅 후보 간의 trade-off:

| 항목 | Gemma4 12B | EXAONE 3.5 7.8B |
|---|---|---|
| 종합 점수 | **9.2** | 8.9 |
| 형식 준수 | **9.3** | 8.6 |
| 논리성 | **9.4** | 9.0 |
| 응답 속도 | ~20s (thinking 활성화) | **6초** (think=false) |
| 모델 크기 | 12B | **7.8B** |
| thinking 모드 | 있음 (품질 경로에서 활성화) | 없음 |
| 역할 | **품질 경로** (진단·보고서·분석) | **속도 경로** (의도 분류) |

**듀얼 모델로 결론**:
1. **품질 0.3점 차이** — 형식·논리성 등 CMS 코파일럿 핵심 축에서 Gemma4 우위
2. **스트리밍 UX** — 프론트엔드가 `/chat/stream` SSE로 구현되어, 20초 대기도 단계 메시지로 체감 단축
3. **Gemma4 thinking 활성화** — 품질 경로에서는 think 파라미터 생략 → thinking ON으로 추론 품질 극대화
4. **EXAONE 속도 경로** — 의도 분류(max_tokens=10)처럼 단순·빠른 작업은 EXAONE 6s 처리
5. **GPT-4o급 가능성** — 내부 평가셋에서 유사한 품질을 확인해 온프레미스 이전 후보로 충분함

## 4. GPT 대비 sLLM 선택 이유

최종 온프레미스 배포에서는 공장 에너지·설비 데이터를 외부 LLM 서비스로 전송하지 않는 구성을 목표로 한다. 현재 RunPod 단계는 모델 품질·VRAM·응답 시간을 검증하기 위한 외부 GPU PoC이므로 실제 온프레미스 운영과 구분한다.

Gemma4는 내부 평가셋에서 **9.2**, GPT-4o는 **9.1**을 기록해 유사한 품질 가능성을 확인했다. 0.1점 차이는 단일 평가 결과이므로 우열보다는 대등한 수준으로 해석한다.

---

## 5. Qwen2.5가 탈락한 이유

복잡한 수치 추론 과정에서 **한국어에서 중국어로 언어가 전환**되는 현상이 발생했습니다.

```
[예지보전 프롬프트 — Qwen2.5 실제 응답 중 발췌]
"... 2024년 4~5月间（April-May 2024）,
COP可能会达到1.5以下的临界值。建议..."
```

공장 운영자가 읽어야 하는 진단 보고서에서 언어 전환은 실사용 불가 수준의 결함입니다.

## 6. 프롬프트 엔지니어링 적용 현황

아래 최적화가 현재 발표용 PoC에 적용되어 있습니다. Gemma4는 thinking 능력 덕에 few-shot 없이도 좋은 결과를 내지만, 형식·도메인 지식 보강은 모든 모델에 유효합니다.

| 적용 위치 | 내용 |
|---|---|
| `cms.py` | 설비 유형별 few-shot (소비/발전 설비 분기) |
| `cms.py` | HIGH/MEDIUM/LOW 심각도 레이블 명확화 |
| `reporting_agent.py` | 섹션별 출력 + 할루시네이션 방지 지시 |
| `report.py` | 일일 브리핑 few-shot (SUMMARY/ACTIONS 형식) |
| `orchestrator.py` | 요금·비용 키워드 report 의도로 추가 + off_topic 거절 라우팅 |
| `rag_agent.py` | 오프토픽 질문 거절 지시 |
| `anomaly_agent.py`, `rag_agent.py`, `cms.py` | 항상 한국어 응답 지시 |
| `domain_knowledge.py` | 계절별 COP/CHP 정상 범위, 역률 정상성, kW/kWh 단위 정의 |

## 8. 결론

**Gemma4 12B**을 최종 채택합니다.

1. **GPT-4o와 대등한 내부 평가 결과** — 33문항에서 Gemma4 9.2/10, GPT-4o 9.1/10.
2. **온프레미스 이전 가능성** — 현재 RunPod PoC 검증 후 동일한 Ollama 구성을 사내 GPU 서버로 이전하는 것이 목표.
3. **한국어·형식 안정성** — 형식 9.3, 논리성 9.4. 보고서·진단 출력 품질 최고.
4. **thinking 활성화** — 품질 경로(진단·보고서·분석)에서는 think 파라미터 생략 → thinking ON으로 추론 품질 극대화.
5. **듀얼 모델** — EXAONE(fast=True)이 의도 분류 등 단순 작업을 6s에 처리. 전체 체감 속도 개선.
6. **스트리밍 UX** — 프론트엔드 SSE 스트리밍으로 단계 메시지 표시, 체감 대기 단축.
7. **라이선스** — Apache 2.0, 상업적 사용 가능.
