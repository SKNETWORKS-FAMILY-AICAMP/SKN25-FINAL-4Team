3 AI 에이전트 — LangGraph 멀티에이전트

LangGraph 상태 기계 기반 멀티에이전트

항목내용
무엇LLM 기반 멀티에이전트 워크플로우를 상태 기계(State Machine)로 구성하는 프레임워크. LangChain 팀 제작.
사용 버전>=0.1.0
핵심 개념StateGraph: 노드(에이전트)와 엣지(라우팅)를 정의. 상태(AgentState)가 노드 사이를 흘러다님.

이 프로젝트에서의 구조

사용자 질문 │ ▼ [classify 노드] ← 키워드 룰 우선, 모호하면 LLM(EXAONE fast) 폴백 │ ├─ anomaly → [anomaly_agent] → DB에서 이상탐지 결과 조회 + LLM 분석 ├─ report → [reporting_agent] → KPI 집계 + LLM 보고서 생성 ├─ forecast → [forecast_agent] → v84 앙상블 추론 + LLM 요약 ├─ cms → [cms_agent] → 설비 진단 + LLM 원인 분석 ├─ rag → [rag_agent] → pgvector 검색 + LLM 답변 └─ off_topic → [rejection_node] → LLM 호출 없이 거절 (즉시 반환) │ ▼ [critic 노드] ← 에너지 도메인 용어 교정 (8개 패턴) │ ▼ 최종 답변

의도 분류 상세

  • 1차 방어: 23개 정규식 키워드 룰 (LLM 호출 없음, <1ms)
  • 2차 방어: LLM 폴백 — EXAONE fast 모드, max_tokens=10, ~6s
  • 오프토픽 차단: _KW_OFFTOPIC 패턴(주식·요리·날씨 등) → 즉시 거절

LangChain Core 기반 추상화 라이브러리

항목내용
무엇LangGraph가 의존하는 기반 라이브러리. 메시지 포맷, 프롬프트 템플릿 등 공통 추상화.
사용 버전>=0.0.400

LangGraph 내부에서 사용. 직접 노출되는 API는 아님.

6 ML 예측 모델 — v84 앙상블

앙상블 아키텍처

입력: 최근 250시간 전력 데이터 (1시간 간격) │ ▼ [전처리] 잔차 타겟 (P(t) − P(t−1)) + 시간/계절 피처 │ ├── LSTM ×6개 (다양한 은닉층·드롭아웃 조합) ├── CatBoost ├── LightGBM ×2 ├── Ridge Regression └── Seasonal Naive (계절 기준선) │ ▼ [앙상블] 가중 평균 (계량기별 최적 가중치) │ ▼ 출력: 1시간 후 / 3시간 후 전력 예측 (kW)
45개 계량기 개인화 — 계량기마다 별도 모델 학습 및 아티팩트 저장. 총 ~589MB.

  • v63·v67·v71 세 버전의 LSTM 예측을 중앙값(median)으로 앙상블
  • 검증 데이터 기반 시간대별 shrunk bias correction × gain 1.30 후처리 적용

7 ML 이상탐지 모델

2경로 이상탐지 구조

[주력 경로] v84 LSTM 잔차 비율 기반 (artifacts 있을 때) LSTM 예측값과 실젯값의 잔차를 계량기별 임계값(threshold)으로 나눈 비율: ratio = |actual - predicted| / threshold → ratio ≥ 2.0 = HIGH | ≥ 1.5 = MEDIUM | ≥ 1.0 = LOW ※ IsolationForest는 이 경로에서 미사용 (if_flag 고정 0) [폴백 경로] 3단 투표 (v84 artifacts 없을 때) 통계 기반 (Z-score, IQR, STL 잔차) IsolationForest LSTM-AE (오토인코더 재구성 오차) → 3표 = HIGH | 2표 = MEDIUM | 1표 = LOW

이상 유형 분류

유형설명
CHPOutageCHP 발전 중단 감지
PowerSpike전력 급증
COPDrop냉난방 성능 계수 급락
NightConsumption야간 비정상 소비
PVNightNonZeroPV 야간 비영 발전 (센서 이상)
LSTM-AE (오토인코더): 정상 데이터로만 학습 → 이상 데이터 입력 시 재구성 오차가 커짐. 오차 > 임계값 = 이상.

Docker + Docker Compose 컨테이너

항목내용
무엇컨테이너 기반 앱 패키징·실행 도구. "내 컴퓨터에서는 됐는데" 문제 해결.
버전Docker 23.0+ / Compose v2
 
# docker-compose.yml 서비스 구성
services:
  backend:   FastAPI (port 8000) + ML 모델 볼륨 마운트
  frontend:  React 빌드 → Nginx (port 8080)
컨테이너 시작 시 ensure_artifacts.py 자동 실행 → HF Hub에서 없는 모델만 다운로드.

RunPod GPU 클라우드

항목내용
무엇GPU 클라우드 서비스. 시간당 과금으로 RTX 3090 등 GPU 대여.
사용 GPURTX 3090 24GB (Secure Cloud)
용도Ollama 서버 — Gemma4:12B + EXAONE 3.5:7.8B 동시 서빙

RunPod Pod 내:
  ollama serve (OLLAMA_HOST=0.0.0.0)
  └── gemma4:12b       (~8GB VRAM)
  └── exaone3.5:7.8b   (~5GB VRAM)

외부 접근: https://{pod-id}-11434.proxy.runpod.net/v1
