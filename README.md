## 프로젝트 개요

Honda R&D Europe 공개 EMS 데이터를 실증용 대체 데이터로 삼아, **예측·이상탐지·LLM 운영지원까지 잇는 분석 파이프라인**을 검증한다.

```
EMS 데이터 → 분석 엔진 → FEMS 운영지원
```

| 구분 | 내용 |
|---|---|
| 프로젝트명 | SKN25 FINAL — 스마트팩토리 에너지 인사이트 |
| 적용 대상 | 중소 제조공장 (한국 제조업 FEMS) |
| 실증 데이터 | Honda R&D Europe EMS (공개 데이터셋) |
| 타겟 비즈니스 | B2B SaaS 구독 (베이직 / 스탠다드 / 프리미엄 3-Tier) |

## 문제 정의

### 외부 압력과 EMS 데이터

| 외부 압력 | 내용 |
|---|---|
| **EU CBAM** | 탄소국경조정세도 본격 적용 |
| **K-ETS 고도화** | 국내 배출권 거래세 규제 강화 |
| **탄소중립 정책** | 운영 효율 가시화와 입증 책임 |
| **에너지 비용 상승** | 피크 수요와 계약전력 관리 부담 |

> **핵심**: EMS 데이터는 이미 쌓이고 있지만, 데이터의 존재만으로 운영 판단이 자동화되지 않는다. 예측·이상탐지·설비 진단·LLM 운영지원으로 잇는 활용 체계가 필요하다.

### 해석 경계

- 계량기·데이터 품질 문제를 먼저 분리
- 잔여 패턴은 **설비 점검 후보로 제시** — 고장 확정 표현은 사용하지 않음
- Honda EMS는 실증용 대체 데이터, 적용 대상은 한국 제조업 FEMS
- 피크 비용은 수요요금·피크 리스크의 대응 지표로 해석
- LLM은 모델 결과와 문서 근거를 요약하는 **운영 지원 기능으로 한정**

### DB 계층 구조

```
source_file → full_measurement → cr_measurement_1h / cr_measurement_15min → VIEW: reduced_measurement_*
```

- **DBMS**: PostgreSQL + TimescaleDB (`ems` schema)
- **계량기 계층**: 건물 4동, 변압기에서 설비 계량기까지 (Honda EMS 계량기 계층도 기준)

| 테이블 | 역할 |
|---|---|
| `full_meter` | 계량기 식별자 registry |
| `full_measurement_definition` | measurement code / unit / family 딕셔너리 |
| `full_source_file` | 파일 단위 적재 상태 및 품질 counter |
| `full_measurement` | 모든 processing level 측정값 fact table |
| `cr_measurement_1h` | 1시간 해상도 mart (TimescaleDB hypertable) |
| `cr_measurement_15min` | 15분 해상도 mart (TimescaleDB hypertable) |

## EDA — 물리적 기준 정의

측정 변수별 정상 범위와 이탈 시 1차 해석 기준 (참고: physical anomaly report §3)

| 측정 변수 | 의미 | 정상 범위 / 물리 기준 | 이탈 시 1차 해석 |
|---|---|---|---|
| **U1 / U2 / U3** | 상별 전압 | 설비 전압 계통의 허용 범위 안 | 전압 이상이나 결선·계량기 문제 |
| **I1 / I2 / I3** | 상별 전류 | 음수 불가, 설비 용량 범위 안 | 센서 오류, 결측 보정, 비정상 부하 |
| **PF** | 역률 | -1 ≤ PF ≤ 1 | 계량방향, 부호 규약, 계량기 이상 |
| **P** | 유효전력 | 소비·생산 방향에 따른 부호 해석 | 소비, 발전, 역송전, 부하 변화 |
| **W** | 누적 전력량 | 단조 증가 또는 명확한 방향성 | 리셋, 결측, 계량기 교체, 원천 문제 |

### 핵심 EDA 관찰

**STL 분해 (H2.Z66 · P)**
- 추세·계절성·잔차로 분해하여 월별 운전 패턴과 회복 추세 확인
- 월별 median 기준 최고 10월, 최저 1월

**PF 국소 이상 (H2.Z66 · PF)**
- 물리 범위(-1 ≤ PF ≤ 1)를 크게 벗어나는 구간 **39건** 식별
- 이 spike는 설비 고장이 아닌 **계량기·데이터 품질 후보**로 먼저 분리

## 모델링과 이상탐지 — 두 개의 레인

### 레인 A · 모델링 — 전력 사용량과 피크 위험 예측

| 단계 | 내용 |
|---|---|
| **L1 후보 모델 비교** | LSTM · SVR · XGBoost를 단변량과 다변량 조건에서 비교 |
| **L2 예측 구성** | 최근 24시간 입력 → 다음 1시간 사용량 예측 |
| **L3 FEMS 연결** | 피크 위험 사전 알림과 동시 고부하 설비군 식별 |

- 2019년 최대 피크: **695.9 kW** (±24시간 분석)
- 피크 삭감 시나리오: 10 / 25 / 50 kW 삭감 폭별 연간 절감 추정

### 레인 B · 이상탐지 — 계량기 → 설비

| 단계 | 내용 |
|---|---|
| **A1 계량기·원천 점검** | zero, leaf, gap 등 계량기와 원천 데이터 문제를 먼저 분리 |
| **A2 잔여 패턴 탐지** | 계량기로 설명되지 않는 잔여 패턴을 점검 후보로 검토 |
| **A3 운영자 우선순위 제시** | 고장으로 단정 짓지 않고 점검 순서로만 제시 |

### A-clean 1시간 전력 예측 실험 결과 (Huang 2022 Benchmark)

**입력**: 직전 24시간 전력값(lag) + 시간 주기(hour_sin, hour_cos)  
**데이터 분할**: 학습 2018–2021 / 검증 2022 / 평가 2023

| 설비군 | 최적 모델 | 2022 RMSE | 2023 RMSE |
|---|---|---|---|
| 중앙 냉방 | LSTM (hidden=32) | 6,963.95 | 4,974.17 |
| 국소 냉방 | XGBoost (n=300, depth=5, lr=0.06) | 1,739.83 | 1,922.54 |
| 서버 전원 | SVR linear (C=1, ε=0.1) | 1,444.62 | 1,782.56 |
| 환기 계통 | XGBoost (n=300, depth=5, lr=0.06) | 3,041.69 | 3,957.79 |

## LLM Agent 구성

| 에이전트 | 역할 |
|---|---|
| **Orchestrator** | 사용자 질의 의도 파악 및 하위 에이전트 라우팅 (LangGraph 기반) |
| **RAG Agent** | 문서·데이터 정의·이상탐지 기준에 근거 검색 (pgvector) |
| **Anomaly Agent** | 3단계 이상탐지 모델 호출 및 점검 후보 정리 |
| **Reporting Agent** | 분석 결과 요약·리포트 자동 생성 |
| **Critic Agent** | 해석 경계와 근거 누락 점검, 분석 오류 자동 탐지 |

## 예상 결과 — FEMS 운영지원 프로토타입

**5계층 아키텍처**

| 계층 | 구성 요소 |
|---|---|
| **01 데이터 계층** | 전처리, PostgreSQL · TimescaleDB, Redis |
| **02 EDA 계층** | 정상 범위, 상관관계, STL, 슬라이딩 윈도우 |
| **03 예측과 이상탐지** | 전력·피크 예측 모델, 3단계 이상탐지 |
| **04 LLM Agent** | Orchestrator, RAG, 이상탐지, 리포팅, Critic |
| **05 서비스와 시연** | FastAPI, React, 챗봇, 자동 리포트, README |

**end-to-end 시연 시나리오**

```
01  운영자 → 챗봇     피크 위험이나 이상 후보를 자연어로 질의
02  RAG Agent         문서·데이터 정의·이상탐지 기준에 근거 검색
03  분석 엔진         예측 모델과 이상탐지 결과를 호출 → 점검 후보 정리
04  Reporting·Critic  결과를 요약하고 해석 경계와 근거 누락을 점검
05  운영자 ← React   대시보드 화면 또는 자동 리포트로 결과 확인
```
