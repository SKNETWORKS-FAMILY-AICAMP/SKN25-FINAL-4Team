SKN25 Final - Energy AI Model

모델 구조와 최종 모델 선택 파이프라인

이 문서는 skn25_final의 확인된 코드 기준으로 에너지 이상탐지 모델 energy_v84가 어떤 입력을 받아 어떤 후보 모델을 만들고, 어떤 기준으로 최종 모델을 선택하는지 정리한다.

기준 모델: energy_v84 서비스 horizon: 3h 학습 대상: 51개 계량기 추론 대상: 63개 계량기 선택 기준: validation MAE 중심
요약 데이터 구조 학습 파이프라인 최종 모델 선택 추론 파이프라인 산출물 P-Max 근거 파일

1. 한 장 요약

Problem
예측 기반 이상탐지

정상 패턴에서 기대되는 P를 예측하고, 실제 또는 운영 threshold와 비교해 이상 가능성을 판단한다.

Training
51

전이 멤버를 제외한 대표, 단독, 전이 실패 계량기만 직접 학습한다.

Serving
63

직접 학습 계량기 51개와 대표 모델을 공유하는 전이 멤버 12개를 모두 추론한다.

Core Idea

단일 모델 하나를 고정하지 않고, 검증 구간에서 이긴 모델만 통과시킨다.

v84는 LSTM, GRU, CatBoost, LightGBM, Ridge, Seasonal Naive를 한 번에 섞는 단순 앙상블이 아니다. 계량기별, 그룹별 validation MAE를 기준으로 단계별 후보를 걸러내고, 개선 폭이 충분할 때만 더 복잡한 후보로 교체한다.

Final Layer

v84 = median(v63, v67, v71) + 시간대별 bias 보정

마지막 단계는 v63 라우팅 결과, Ridge, Seasonal Naive를 median으로 합치고, validation 잔차에서 계산한 시간대별 shrunk bias correction을 적용한다.

중요: 이 문서의 최종 선택 흐름은 코드상 학습 파이프라인 기준이다. 운영 경보 threshold는 별도 artifacts/thresholds/val_thresholds.csv 기준으로 관리되며, 학습 코드 내부의 anomaly_threshold와 같은 개념으로 단정하면 안 된다.

3. 학습 파이프라인

학습은 크게 2패스로 구성된다. 1패스는 LSTM 계열 후보를 만들고, 2패스는 부스팅, 선형 모델, 나이브 모델, 라우팅, 최종 앙상블을 결합한다.

Pass 1 - LSTM 계열 후보 생성

버전 구조 Window 특징
v1LSTM24h시간 feature 미사용 기본형
v2LSTM24h시간 feature 사용
v3LSTM168h주간 패턴 반영
v4GRU24hLSTM 대체 recurrent 구조
v6LSTM24hdropout 0.2로 정규화
v7LSTM24hSmoothL1 loss 사용

Pass 2 - 모델 라우팅과 최종 앙상블

v19 그룹/역할 단위로 v10, v12, v15 중 median validation MAE가 가장 낮은 후보 선택.
v24/v25/v36 convex weight 탐색, 개선 gate, median residual bias 보정.
v52/v53/v57 넓은 후보 gate, CatBoost, 계량기별 라우팅.
v61/v63 LightGBM 후보와 v57을 그룹 평균 MAE로 비교.
v67/v71 Ridge와 Seasonal Naive를 최종 앙상블 후보로 추가.
v84 median ensemble 후 시간대별 shrunk bias correction 적용.

4. 최종 모델 선택 구조

최종 모델은 “가장 복잡한 모델을 무조건 선택”하지 않는다. 각 단계에서 validation MAE가 기준 모델보다 충분히 개선될 때만 다음 후보가 채택된다.

PNG 초안처럼 고도화 흐름이 보이도록 후보 모델, 앙상블, gate, routing, 최종 보정 단계를 직접 배치했다. 마지막에는 예측값 생성에서 끝내지 않고, actual P를 validation 구간 actual P 기반 threshold band와 비교해 HIGH/LOW warning을 판정하는 단계를 추가했다.

v10
v3을 제외한 LSTM 후보 중 전체 horizon 기준 validation MAE 상위 2개를 inverse-MAE 가중 평균으로 결합한다.
모델 설명: 여러 LSTM 변형 중 성능이 좋은 두 개를 섞은 기본 앙상블이다.
top-2 weighted
v12
forecast step별로 validation MAE 상위 2개 LSTM 후보를 따로 선택한다.
모델 설명: 예측 시점마다 잘 맞는 LSTM 조합이 다를 수 있어 step별로 후보를 고른다.
stepwise top-2
v15
forecast step별로 validation MAE 상위 3개 LSTM 후보를 따로 선택한다.
모델 설명: top-2보다 후보 폭을 넓혀 특정 step에서 놓치는 패턴을 보완한다.
stepwise top-3
v19
그룹과 역할 단위에서 v10, v12, v15의 median validation MAE를 비교해 기본 LSTM ensemble을 고른다.
모델 설명: 계량기 특성이 비슷한 그룹 단위로 가장 안정적인 LSTM 앙상블을 선택한다.
group median MAE
v24
v10, v12, v15를 0.1 단위 convex weight grid로 섞어 validation MAE가 가장 낮은 조합을 찾는다.
모델 설명: 후보 앙상블의 가중치를 직접 탐색해 단순 평균보다 나은 조합을 찾는다.
grid search
v25
v24가 v19보다 0.1% 이상 개선될 때만 v24를 사용하고, 아니면 v19를 유지한다.
모델 설명: 새 조합이 아주 조금 좋아 보이는 경우를 걸러내기 위한 성능 gate다.
+0.1% 이상
v36
v25의 validation residual median을 사용해 bias를 보정한 후보를 만든다.
모델 설명: 특정 계량기/시간대에서 반복되는 예측 치우침을 잔차 기반으로 보정한다.
bias candidate
v52
v10, v12, v15, v19, v25, 조건부 v3 중 v25보다 나은 후보가 있으면 교체하고, 검증상 유리하면 bias 보정도 적용한다.
모델 설명: 기존 후보를 넓게 다시 비교해 계량기별로 더 나은 source를 찾는 단계다.
broad source gate
v53
CatBoost 후보를 별도로 학습한다.
모델 설명: 트리 부스팅 계열 후보로, LSTM이 놓치는 비선형 feature 상호작용을 보완한다.
boosting
v57
계량기별로 v52, v53, v36을 비교한다. v52보다 0.25% 이상 개선될 때만 다른 후보로 교체한다.
모델 설명: 모든 계량기에 같은 모델을 강제하지 않고, 계량기별로 더 좋은 후보를 라우팅한다.
+0.25% 이상
v61
LightGBM 후보를 계량기별로 학습한다.
모델 설명: 빠르고 안정적인 부스팅 후보로, 그룹 라우팅 비교에 사용할 대안 모델이다.
boosting
v63
그룹 평균 validation MAE 기준으로 v57과 v61을 비교한다. 0.1% 이상 개선될 때만 v61을 선택한다.
모델 설명: 계량기별 선택 결과와 LightGBM 후보를 그룹 단위로 다시 비교해 운영 경로를 안정화한다.
+0.1% 이상
v84
v63, Ridge(v67), Seasonal Naive(v71)를 median으로 합친 뒤 validation 잔차 기반 시간대별 보정을 적용한다.
모델 설명: 라우팅 결과, 선형 후보, 계절성 baseline을 median으로 결합하고 시간대별 편향을 보정한 최종 모델이다.
final ensemble
왜 gate를 두는가: 복잡한 후보가 특정 validation 구간에서 우연히 비슷한 성능을 내는 경우를 막기 위해, 기준 모델 대비 최소 개선률을 만족할 때만 교체한다. 이 구조는 모델 복잡도 증가가 실제 성능 개선으로 이어지는지 확인하는 안전장치다.

5. 추론 및 경보 파이프라인

1. 기준 시각 선택 forecast_origin_ts 기준으로 t+1, t+2, t+3을 예측한다.
2. 입력 조회 최근 history를 조회해 window와 lag feature 계산이 가능한지 확인한다.
3. 품질 점검 물리 룰, 결측, 보간 가능 여부를 점검하고 불충분하면 insufficient_data로 기록한다.
4. 모델 로드 학습 계량기는 자기 artifact, 전이 멤버는 대표 artifact를 사용한다.
5. 예측 복원 잔차 예측에 anchor P(t-1)를 더해 실제 P 단위로 복원한다.
6. 경보 판단 운영 threshold와 비교해 high, low, none 경보 방향을 정한다.

운영 출력 상태

status 의미 사용자에게 보여줄 해석
success 추론 성공 예측값과 경보 방향을 신뢰 가능 범위에서 표시
insufficient_data 필요한 입력 history, 최신 bucket, 또는 feature 품질이 부족함 모델 장애가 아니라 입력 데이터 부족으로 예측 보류
no_artifact 해당 계량기에 사용할 모델 artifact가 없음 모델 배포 또는 mapping 점검 필요
error 예상하지 못한 코드, 파일, 실행 오류 서버/모델 실행 오류로 점검 필요

7. P-Max 모델 파이프라인

P-Max는 이상탐지와 달리 최대수요 또는 피크 전력 예측을 목표로 한다. 입력은 15분 단위 peak feature이며, 최근 24시간 window를 사용해 다음 60분의 P_max를 15분 간격 4스텝(t+15, t+30, t+45, t+60)으로 예측한다.

P-Max도 window와 feature engineering은 Input Preparation 안에 포함된다. 이후 LightGBM, XGBoost, CatBoost 후보를 같은 입력으로 비교하고, validation RMSE 기준의 가중 앙상블로 다음 60분의 P_max를 예측한다.

구분 Anomaly Detection P-Max
목표 계량기별 예상 P와 threshold 기반 이상 경보 다음 60분의 피크 전력(P_max) 예측
입력 단위 feature window 15분 단위 peak feature, 최근 24시간 window
주요 선택 기준 validation MAE와 단계별 개선 gate validation RMSE 기반 후보 비교 및 최종 가중 앙상블
모델 선택 방식 후보 모델, 계량기별 라우팅, 그룹 라우팅, bias correction을 단계적으로 결합 LightGBM, XGBoost, CatBoost 후보 예측을 validation RMSE 기준 가중 앙상블로 결합
운영 산출물 계량기별 artifact, routing metadata, threshold, validation summary 후보 모델 파일, manifest.json, ensemble_weights.csv, P-Max 전용 validation/promotion artifact
