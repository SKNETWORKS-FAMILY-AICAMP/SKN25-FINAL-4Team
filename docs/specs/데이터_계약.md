# EMS 데이터 계약 명세

**갱신일:** 2026-05-08  
**범위:** DB에서 전처리, 피처 생성, 이상탐지, 예측으로 전달되는 분석 입력 규칙.

---

## 1. 원천 기준

EMS 분석 입력의 원천은 PostgreSQL/TimescaleDB `ems` schema다. 로컬 파일 디렉터리는 분석 원천으로 사용하지 않는다.

| 계층 | 사용 기준 |
|---|---|
| `ems.cr_measurement_15min` | 초기 탐색, 전처리 검증, feature baseline의 기본 입력 후보 |
| `ems.cr_measurement_1h` | 보고 지표, 장기 추세, 예측 baseline 입력 후보 |
| `ems.cr_measurement_all` | `15min`, `1h` union 조회가 필요할 때 사용 |
| `ems.full_measurement` | 전체 처리 계보 분석 또는 full 적재 재개 시 사용 |
| `ems.full_source_file` | 파일 단위 적재 상태, row counter, lineage 확인 |
| `ems.full_measurement_definition` | measurement code, unit, family, description 기준 |
| `ems.full_meter` | meter URN registry 기준. 계량기 classification 기준은 `docs/specs/계량기_메타데이터.md`에서 관리한다. |

`cr_measurement_*` 계층은 `corrected_resampled` 처리 단계의 분석용 mart로 취급한다. PostgreSQL 1min mart는 운영 저장 대상에서 제외했으며, 상세 event 분석은 archive 또는 Parquet 계층에서 필요한 범위만 조회한다.

---

## 2. 분석 입력 grain

### 2.1 기본 row grain

```text
(ts, meter_urn, measurement, resolution_code)
```

CR mart 개별 table에서는 `resolution_code`가 table명으로 고정된다. `cr_measurement_all` 또는 분석 코드에서 resolution을 명시할 때는 PostgreSQL mart 기준 `15min`, `1h`를 사용한다. `1min`은 DB mart가 아니라 archive 조회 대상으로 구분한다.

### 2.2 기본 column 계약

| Column | Type | 의미 | 규칙 |
|---|---|---|---|
| `ts` | `timestamptz` | 측정 시각 | UTC 기준으로 조회하고 정렬한다. |
| `meter_urn` | `text` | 계량기 식별자 | `ems.full_meter.meter_urn` 기준으로 검증한다. |
| `measurement` | `text` | 측정 항목 코드 | `ems.full_measurement_definition.measurement` 기준으로 검증한다. |
| `value` | `double precision` | 측정값 | NULL 허용. 단위 변환 없이 원 DB 값을 사용한다. |
| `source_file` | `text` | 원천 파일 식별자 | lineage와 row counter 확인에 사용한다. |
| `resolution_code` | `text` | 해상도 | 개별 CR table 조회 시 분석 코드에서 명시한다. |

---

## 3. 시간 기준

1. DB 조회 조건은 UTC 기준 `timestamptz`로 작성한다.
2. 기간 조건은 반개구간 `[start_ts, end_ts)`를 기본으로 사용한다.
3. 로컬 시간 해석이 필요한 보고 지표는 `Europe/Berlin` 기준으로 별도 변환한다.
4. DST 전환 구간은 UTC 시계열을 기준으로 먼저 검증한 뒤 로컬 시간 feature를 생성한다.
5. 분석 코드에서는 `ts` 정렬 후 중복 여부와 간격 누락 여부를 해상도별로 확인한다.

---

## 4. Measurement 식별자 기준

1. 분석 코드는 DB 적재명 기준 measurement code를 사용한다.
2. 기상 absolute humidity는 `Ah`를 사용한다.
3. 일사량 global 항목은 `Igc`를 사용한다.
4. 원천 문서 표기 차이는 `docs/specs/프로젝트_개요.md`의 기준 데이터와 DB 적재명 기준을 우선한다.
5. `Pa`는 registry에는 유지하지만 `full_source_file` metadata에서 확인되지 않았으므로 기본 분석 입력에서 제외한다.
6. `Quality`는 물리 measurement가 아니며 source file metadata에서 확인되지 않았으므로 기본 분석 입력에서 제외하고 DB cleanup 후보로 둔다.
7. `Tdiff`는 `mK`를 최종 단위 기준으로 사용한다. Kelvin 단위 feature가 필요하면 `value / 1000`으로 별도 파생한다.

---

## 5. Resolution 사용 기준

| Resolution | 사용 범위 | 비고 |
|---|---|---|
| `15min` | 초기 feature baseline, 결측률 검증, 이상탐지 baseline | 계산량과 시간 해상도의 균형 기준 |
| `1h` | 보고 지표, 장기 추세, 예측 baseline | 월간·일간 aggregate와 연결 |
| `1min` | 상세 event 분석, 고해상도 이상탐지 | PostgreSQL mart 제외. archive 또는 Parquet 계층에서 범위 제한 조회 |

초기 전처리 및 feature 설계 문서는 `15min`을 기본 해상도로 사용한다. `1min`은 DB 기본 입력이 아니며 기간, meter, measurement 범위를 제한한 event-level 분석에 사용한다.

## 6. 품질 검증 기준

| 검증 항목 | 기준 table/view | 처리 규칙 |
|---|---|---|
| source file status | `ems.full_source_file` | `status='loaded'` 파일만 기본 입력으로 사용한다. |
| row balance | `ems.full_file_load_balance` | `unaccounted_rows`가 0이 아닌 파일은 검증 대상으로 표시한다. |
| NULL value | CR mart, `full_source_file.null_value_rows` | 결측률과 연속 결측 길이를 산출한다. |
| non-finite | `full_source_file.non_finite_rows` | DB 적재 시 NULL 처리 기준과 분석 입력 기준을 맞춘다. |
| duplicate/conflict | `full_source_file` counters | 중복 발생 파일은 lineage 확인 대상으로 분리한다. |
| measurement registry | `full_measurement_definition` | dictionary에 없는 measurement는 분석 입력에서 제외한다. |
| meter registry | `full_meter` | registry에 없는 meter는 분석 입력에서 제외한다. |

## 7. Feature 생성 입력 기준

### 7.1 전처리 입력

전처리 함수는 long format을 기본 입력으로 받는다.

```text
(ts, meter_urn, measurement, value, resolution_code, source_file)
```

전처리 단계에서는 다음 정보를 추가할 수 있다.

| Column | 의미 |
|---|---|
| `unit` | measurement definition 기준 단위 |
| `measurement_family` | 전기, 열·냉방, 기상 계열 구분 |
| `meter_group` | DB registry 또는 ontology helper의 equipment group |
| `quality_flag` | 결측, 중복, 이상치, counter mismatch 표시 |

상세 feature 생성 규칙, naming, redundancy 처리, live replay 누수 방지 기준은 `docs/specs/피처_명세.md`를 따른다.

### 7.2 Wide format 전환 기준

Wide format은 모델 입력 직전에 생성한다. 전환 전 다음 조건을 확인한다.

1. `(ts, meter_urn, measurement, resolution_code)` 중복이 없어야 한다.
2. pivot 대상 measurement의 unit과 family가 확정되어야 한다.
3. 결측 처리 방식이 feature별로 정의되어야 한다.
4. meter classification metadata가 필요한 aggregate는 `docs/specs/계량기_메타데이터.md` 또는 DB 승격 table 기준이 확정된 뒤 생성한다.

---

## 8. Aggregate 기준

Aggregate feature는 원천 row를 대체하지 않는다. 원천 row와 aggregate row의 계보를 분리한다.

| Aggregate 단위 | 필요 metadata | 사용 예 |
|---|---|---|
| building | meter URN의 building code 또는 classification | 건물별 전력 사용량 |
| equipment | meter classification | CHP, PV, 냉각기, 서버 계통 분석 |
| measurement family | measurement dictionary | 전력, 열, 냉방, 기상 계열 요약 |
| time bucket | UTC timestamp 및 로컬 시간 feature | 일간, 주간, 월간 지표 |

meter classification table이 DB에 정규화되기 전에는 aggregate 결과를 후보 산출물로 표시한다.

---

## 9. 제외 기준

다음 항목은 기본 분석 입력에서 제외한다.

1. source file metadata에서 확인되지 않은 measurement.
2. `status` 값이 `loaded`와 다른 source file의 row.
3. registry에 없는 meter 또는 measurement.
4. 단위 해석이 확정되지 않은 파생 feature.
5. PostgreSQL mart에서 제외한 1min 원천을 DB mart처럼 가정한 검증 결과.

---

## 10. 저장소 경계

| 데이터 범위 | 기준 저장소 | 사용 기준 |
|---|---|---|
| 기준 metadata, registry, 15min/1h 분석 mart | PostgreSQL/TimescaleDB `ems` schema | 기본 분석 입력 |
| 전체 raw, harmonized, corrected native, 장기 1min 보관본 | Parquet archive 또는 승인된 외부 원천 경로 | 범위 제한 event-level 분석, 재적재 검증 |
| 재생성 가능한 분석 산출물 | `outputs/`, `reports/` | 커밋 대상이 아닌 실행 산출물 |

`1min` 데이터는 기본 PostgreSQL mart로 가정하지 않는다. 필요한 분석에서 기간, meter, measurement 범위를 명시해 조회한다.

## 11. 후속 확정 항목

1. `Quality` definition DB cleanup 실행 여부 결정.
2. 1min archive 또는 Parquet 계층의 event-level 조회 helper 작성 여부 결정.
3. `docs/specs/계량기_메타데이터.md`의 DB 승격 결정 기준에 따라 meter classification 및 redundancy metadata 적용 승인 여부 결정.
4. `docs/specs/피처_명세.md` 기준에 따라 feature table 저장 위치와 명명 규칙 확정.
