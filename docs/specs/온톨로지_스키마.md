# EMS Ontology Schema 명세

**갱신일:** 2026-05-08  
**범위:** EMS 계량기 metadata, 설비 group, 건물, 역할, redundancy 관계의 formal ontology 초안.

---

## 1. 목적

이 문서는 EMS ontology artifact의 class, property, relationship, constraint 후보를 정의한다. 시계열 measurement row는 PostgreSQL/TimescaleDB에서 관리하고, ontology는 metadata와 관계 해석을 담당한다.

## 6. Constraint 후보

| Constraint | 현재 적용 방식 | 향후 formalization 후보 |
|---|---|---|
| 모든 meter는 하나의 equipment group을 가진다 | generation validation 및 SHACL validation | OWL cardinality 1 |
| 모든 meter는 하나의 building code를 가진다 | generation validation 및 SHACL validation | OWL cardinality 1 |
| 모든 meter는 하나의 role을 가진다 | generation validation 및 SHACL validation | OWL cardinality 1 |
| redundancy pair는 primary와 redundant meter를 각각 하나씩 가진다 | generation validation 및 SHACL validation | OWL cardinality 1 |
| weather meter는 energy aggregate에 포함하지 않는다 | feature contract 후보 | SHACL 또는 rule 문서 |
| production meter의 음수 value는 발전값으로 보존한다 | `계량기_메타데이터.md` | rule 문서 |
| redundant pair는 기본 aggregate에서 중복 합산하지 않는다 | feature contract 후보 | rule 문서 |
| 모든 meter는 부호 규약을 가진다 | generation validation | role 기반 rule |
| 모든 equipment group은 이상탐지 우선순위를 가진다 | generation validation | priority vocabulary 후보 |
| 모든 equipment group은 기본 검토 view를 가진다 | generation validation | visualization constraint 후보 |

추가 mapping coverage는 다음을 만족해야 한다.

1. 모든 meter는 `belongsToGroup`, `locatedInBuilding`, `hasRole`, `meterDomain`, `meterUrn`, `noteFile`, `signConvention`, `anomalyPriority` 값을 가진다.
2. 모든 equipment group은 `meterCount`, `primaryView`, `anomalyPriority`, `noteFile` 값을 가진다.
3. Redundancy pair는 `hasPrimaryMeter`, `hasRedundantMeter`, `hasGroup`을 각각 하나씩 가진다.
4. `redundantWith`는 각 redundancy pair에 대해 양방향으로 materialize한다.
5. Focus view가 있는 group은 `visualizedBy`로 해당 Canvas와 연결한다.
6. group 내부 상하위 계층을 명시한 meter는 `equipmentLayer` 값을 가진다.
7. 모든 meter는 `hasHardwareModel`과 `hardwareModelCode` 값을 가진다.

## 8. EMS 분석에서의 사용

### 8.1 Feature 설계

Ontology는 feature 생성 시 포함·제외 기준을 제공한다.

예시:

```text
equipment_group = central_cooling
meter_domain = electricity
meter_role = consumption
redundant pair 제외 또는 primary 우선
```

### 8.2 Live replay anomaly 설명

Anomaly event가 meter 단위로 발생하면 다음 context를 결합한다.

```text
meter → equipment group → building → role → redundancy pair → 관련 view
```

### 8.3 LLM grounding

LLM agent는 `docs/ontology/ems.ttl`, `온톨로지_질의.md`, Obsidian note를 함께 읽어 계량기 관계를 확인한다. 확인 없이 계량기 관계를 추정하지 않는다.

---

## 9. Protégé 사용 기준

Protégé는 `docs/ontology/ems.ttl` 또는 `docs/ontology/ems_protege.owl`을 열어 class hierarchy, object property, data property, individual 관계를 검토하는 데 사용한다. `ems_protege.owl`은 Protégé GUI 확인을 위해 함께 생성하는 RDF/XML artifact다. 수동 편집으로 canonical source를 변경하지 않는다. 변경 필요 시 `계량기_메타데이터.md`, Obsidian Properties, 또는 향후 DB metadata table을 수정한 뒤 artifact를 재생성한다.

---

## 10. 제외 범위

1. 6년치 measurement row를 RDF로 변환하지 않는다.
2. 물리 배선도, 차단기 구성, 제어 로직을 확정하지 않는다.
3. DB schema 변경은 이 문서 범위에 포함하지 않는다.
4. Neo4j, Fuseki, GraphDB 같은 server 기반 graph 저장소는 현 단계에서 도입하지 않는다.
