# EMS DB 구조 명세

**갱신일:** 2026-05-08  
**범위:** PostgreSQL/TimescaleDB `ems` schema의 relation, column, index, function 구조.

---

## 1. Schema 개요

```text
ems
├── full_meter                         # meter registry
├── full_measurement_definition        # measurement dictionary
├── full_source_file                   # source file audit and load metadata
├── full_measurement                   # canonical full fact table
├── full_measurement_with_metadata     # full_measurement + dictionary view
├── full_file_load_summary             # source_file 집계 view
├── full_file_load_balance             # source_file row accounting view
├── cr_measurement_1h                  # corrected/resampled 1h hypertable
├── cr_measurement_15min               # corrected/resampled 15min hypertable
├── cr_measurement_all                 # 1h/15min CR mart union view
└── cr_measurement_with_metadata       # CR mart + dictionary view
```

CR mart 계층은 `corrected_resampled` 처리 단계의 15min, 1h 해상도 데이터를 저장한다. PostgreSQL 1min mart는 운영 저장 대상에서 제외하고 제거했다. `full_measurement`는 processing level과 resolution을 row metadata로 수용하는 canonical fact table이다.

현재 저장 기준에서는 PostgreSQL/TimescaleDB를 기준 metadata와 15min/1h curated mart 저장소로 사용한다. 전체 raw, harmonized, corrected native 및 장기 1min 보관본은 Parquet archive 또는 승인된 외부 원천 경로로 분리한다.

Row 수, chunk 수, table size, 적재 진행 상황은 시점성 운영 기록으로 분리하고 active DB 구조 명세에는 relation, column, index, function 기준만 유지한다.

## 2. Registry 및 Dictionary 계층

| Relation | 역할 | Key |
|---|---|---|
| `ems.full_meter` | meter registry | `meter_urn` |
| `ems.full_measurement_definition` | measurement code별 unit, family, description dictionary | `measurement` |
| `ems.full_source_file` | source file 단위 load audit, row accounting, failure tracking | `source_file` |

### 2.1 `full_meter`

| Column | Type | 설명 |
|---|---|---|
| `meter_urn` | `text` | meter identifier |
| `meter_group` | `text` | meter group code |
| `created_at` | `timestamptz` | registry row 생성 시각 |

`full_meter`는 meter URN의 DB registry다. 설비 classification, domain grouping, redundancy relation, anomaly priority metadata는 별도 table로 정규화되어 있지 않다. DB 승격 전 계량기 metadata 명세는 `docs/specs/계량기_메타데이터.md`에서 관리한다.

### 2.2 `full_measurement_definition`

| Column | Type | 설명 |
|---|---|---|
| `measurement` | `text` | measurement code |
| `unit` | `text` | 측정 단위 |
| `measurement_family` | `text` | 측정 계열 |
| `description` | `text` | 측정 항목 설명 |

`full_measurement_definition` 처리 기준:

1. `Pa`는 원천 문서에 존재하는 기상 measurement이므로 registry에 유지한다. 다만 현재 source file metadata에서 확인되지 않았으므로 기본 분석 입력에서는 제외한다.
2. `Quality`는 물리 measurement가 아니며 source file metadata에서도 확인되지 않으므로 기본 분석 입력에서 제외하고 DB cleanup 후보로 둔다.
3. `Tdiff`는 `mK`를 최종 단위 기준으로 둔다. Kelvin 단위 feature가 필요하면 `value / 1000` 파생값을 별도로 생성한다.

### 2.3 `full_source_file`

| Column group | Columns |
|---|---|
| file identity | `source_file`, `meter_urn`, `measurement`, `processing_level`, `resolution_code` |
| input size | `compressed_bytes`, `csv_rows` |
| load result | `inserted_rows`, `conflict_rows`, `duplicate_key_rows` |
| quality counters | `null_value_rows`, `unknown_measurement_file_rows`, `invalid_value_rows`, `invalid_ts_rows`, `non_finite_rows` |
| execution status | `started_at`, `finished_at`, `status`, `error_message` |

## 3. Canonical Full Fact 계층

| Relation | 역할 | 비고 |
|---|---|---|
| `ems.full_measurement` | processing level과 resolution 전체를 수용하는 fact table | regular table |
| `ems.full_measurement_with_metadata` | `full_measurement`와 measurement dictionary 결합 view | metadata view |

Logical key:

```text
(ts, meter_urn, measurement, processing_level, resolution_code)
```

`full_measurement` column 구성:

| Column | Type | 설명 |
|---|---|---|
| `ts` | `timestamptz` | 측정 시각 |
| `meter_urn` | `text` | meter identifier |
| `measurement` | `text` | measurement code |
| `processing_level` | `text` | raw, harmonized, corrected, corrected_resampled |
| `resolution_code` | `text` | native, 1min, 15min, 1h |
| `value` | `double precision` | 측정값, NULL 허용 |
| `source_file` | `text` | `full_source_file.source_file` 참조 |
| `loaded_at` | `timestamptz` | row 적재 시각 |

`full_measurement`는 DB 조회 기준 TimescaleDB hypertable 목록에 포함되지 않는다. `scripts/_archive/ingest/sql/timescaledb.sql`은 hypertable 전환 후보 DDL을 보유한다.

## 4. Corrected/Resampled Mart 계층

| Relation | Resolution | TimescaleDB | Chunk interval |
|---|---|---|---|
| `ems.cr_measurement_1h` | 1 hour | hypertable | 90 days |
| `ems.cr_measurement_15min` | 15 minutes | hypertable | 30 days |

CR mart table column 구성:

| Column | Type | 설명 |
|---|---|---|
| `ts` | `timestamptz` | 측정 시각 |
| `meter_urn` | `text` | meter identifier |
| `measurement` | `text` | measurement code |
| `value` | `double precision` | 측정값, NULL 허용 |
| `source_file` | `text` | `full_source_file.source_file` 참조 |
| `loaded_at` | `timestamptz` | row 적재 시각 |

CR mart table은 `processing_level='corrected_resampled'` 의미를 table 계층에서 고정한다. Resolution은 table명과 `cr_measurement_all.resolution_code`로 표현한다.

## 5. View 계층

| View | 역할 |
|---|---|
| `ems.full_measurement_with_metadata` | `full_measurement`와 `full_measurement_definition` 결합 |
| `ems.full_file_load_summary` | `full_source_file`의 processing level 및 resolution별 집계 |
| `ems.full_file_load_balance` | 파일 단위 CSV row와 accounted row 차이 확인 |
| `ems.cr_measurement_all` | `cr_measurement_1h`, `cr_measurement_15min`의 `UNION ALL` view |
| `ems.cr_measurement_with_metadata` | CR union view와 `full_measurement_definition` 결합 |

`full_file_load_balance` accounted-row 계산식은 다음과 같다.

```text
inserted_rows
+ duplicate_key_rows
+ conflict_rows
+ non_finite_rows
+ invalid_value_rows
+ invalid_ts_rows
```

`unknown_measurement_file_rows`는 결과 column으로 제공되지만 accounted-row 계산식에는 포함되지 않는다. Dask 계열 loader에서 `inserted_rows`는 NULL value row를 포함한 적재 row 수이며, `null_value_rows`는 해당 row의 부분집합 품질 counter다. 따라서 `null_value_rows`는 accounted-row 계산식에 포함하지 않는다.

## 6. Index 및 Constraint 구조

### 6.1 `full_measurement` index

| Index | 목적 |
|---|---|
| `full_measurement_unique_idx` | `(ts, meter_urn, measurement, processing_level, resolution_code)` 중복 방지 |
| `full_measurement_lookup_idx` | meter/measurement/level/resolution 기준 시계열 조회 |
| `full_measurement_processing_ts_idx` | processing level 및 resolution 기준 시간 범위 조회 |
| `full_measurement_source_file_idx` | source file 추적 |
| `full_measurement_ts_brin_idx` | 대용량 시간 범위 scan 보조 |

### 6.2 CR Mart index

| Table | Index |
|---|---|
| `cr_measurement_1h` | `unique`, `lookup`, `source_file`, `ts` index |
| `cr_measurement_15min` | `unique`, `lookup`, `source_file`, `ts` index |

PostgreSQL 1min mart는 운영 저장 대상에서 제외했다. 1min event-level 분석은 archive 또는 Parquet 계층에서 필요한 범위만 조회한다.

### 6.3 Constraint

| Target | Constraint |
|---|---|
| `full_meter` | `meter_urn` primary key |
| `full_measurement_definition` | `measurement` primary key |
| `full_source_file` | `source_file` primary key, `meter_urn` foreign key |
| `full_measurement` | `source_file` foreign key, processing/resolution check |
| `cr_measurement_*` | `source_file` foreign key |
