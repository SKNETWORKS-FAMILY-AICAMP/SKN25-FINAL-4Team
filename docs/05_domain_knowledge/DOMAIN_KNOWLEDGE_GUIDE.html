Domain Knowledge

Energy Metering Domain Knowledge Guide

이 문서는 본 프로젝트에서 전기/열량 계량 데이터를 해석할 때 필요한 기본 도메인 지식을 정리한 문서입니다. 목적은 feature 의미를 이해하고, 계량기가 무엇을 직접 측정하고 무엇을 계산하는지 구분하며, 이상치가 설비 문제인지 계량 문제인지 해석하는 기준을 갖추는 것입니다.

핵심 질문 1

계량기는 단순히 값을 “출력”하는가, 아니면 내부에서 일부 값을 “계산”하는가?

핵심 질문 2

이상치가 보였을 때 그것이 설비 문제인지, 계량 채널 문제인지 어떻게 구분할 것인가?

핵심 질문 3

프로젝트에서 어떤 유형의 이상을 NaN 처리/flag 처리 대상으로 볼 것인가?

1. 계량기는 무엇을 하는 장치인가

계량기는 단순히 설비 옆에 붙어 있는 “표시기”가 아니라, 여러 센서 입력을 받아서 일부 물리량은 직접 읽고, 일부 물리량은 내부 로직으로 계산하여 저장 또는 전송하는 장치입니다.

직접 측정에 가까운 값

  • 전압 U1, U2, U3
  • 전류 I1, I2, I3
  • 주파수 f
  • 외기온 Ta
  • 유량 qv
  • 공급/환수 온도 Tvl, Trl

계산/파생에 가까운 값

  • 유효전력 P
  • 무효전력 Q
  • 역률 PF, PF1, PF2, PF3
  • 누적 전력량 W
  • 온도차 Tdiff = Tvl - Trl
  • 열량계 power P 또는 유사한 열부하 지표
중요: DB에 저장된 값이 모두 “원시 센서값(raw sensor voltage/current signal)”은 아닙니다. 특히 P, Q, PF, W는 보통 계량기 내부 계산이나 장비 firmware 계산을 거친 값입니다.

전기 계량기 예시

전기 계량기는 보통 각 상의 전압, 전류, 위상 정보를 읽은 뒤 이를 조합해 P, Q, PF, W 같은 값을 계산합니다. 따라서 센서 자체가 정상이어도, 내부 계산이나 채널 매핑이 꼬이면 파생 feature가 비정상적으로 튈 수 있습니다.

열량계 예시

열량계는 유량과 공급/환수 온도차를 기반으로 열부하를 계산하는 경우가 많습니다. 따라서 qv, Tvl, Trl 중 하나라도 깨지면 Tdiff나 열 관련 P가 비정상적으로 나올 수 있습니다.

2. 주요 feature 설명

Feature 의미 대략적 성격 직접 측정 / 계산 이상 해석 포인트
P 유효전력 또는 열부하 power 실제 소비/전달되는 에너지율 계산 성격 강함 운전 패턴, 부하 크기, 설비 사용량과 직접 연결
Q 무효전력 위상 차이와 관련된 전력 성분 계산 P와 다르게 움직일 수 있음, PF와 함께 해석
PF 역률 전압-전류 위상 관계 및 효율 지표 계산 |PF| > 1은 물리적으로 비정상, 채널/계산 문제 의심
U1~U3 상별 전압 공급 전압 상태 직접 측정 가까움 0 또는 급락/급등이면 센서/통신 또는 실제 전원 문제 구분 필요
I1~I3 상별 전류 부하 흐름 직접 측정 가까움 P와 함께 보면 부하 원인 파악에 도움
f 주파수 전력계통 안정성 측정 대체로 변화폭이 작아, 급변 시 품질 이슈 의심
W, W_in 누적 전력량 적산값 계산/누적 단기 이상탐지보단 장기 consumption 추적에 유리
Ta 외기온 기상 변수 직접 측정 설비 부하와의 외생 관계 파악용
Igm 일사량 등 기상 관련 입력 외생 변수 측정 PV/태양복사 영향 해석에 사용 가능
qv 유량 유체 흐름 측정 열량계에서 가장 기본적인 flow 지표
Tvl, Trl 공급/환수 온도 열 회수/전달 상태 측정 개별 값보다 차이값 Tdiff가 해석에 더 직접적
Tdiff 온도차 열교환 강도 계산 냉난방 동작 여부, 비정상 열교환 감지에 중요

3. 왜 PF가 11 같은 값을 가질 수 있는가

역률 PF는 정상적으로는 대체로 -1 ~ 1 범위에 있어야 합니다. 따라서 PF = 11.33 같은 값은 물리적으로 해석 가능한 설비 상태가 아닙니다.

물리적으로 불가능한 예:
  • |PF| > 1
  • 전압 <= 0
  • 주파수 <= 0
  • 소비형 설비의 음수 P가 지속
  • 음수 유량, 음수 온도차가 물리 구조상 불가능한 구간

이런 값이 생기는 원인은 보통 다음 중 하나입니다.

  • 센서 입력 이상
  • 상별 채널 매핑 오류
  • 분모가 매우 작아지는 계산 불안정
  • firmware/계량기 내부 계산 오류
  • 통신/저장 과정의 잘못된 값 삽입

4. 이상의 종류: 설비 문제 vs 계량 문제 vs 데이터 품질 문제

프로젝트에서 실무적으로는 이상을 최소 세 가지로 나누는 편이 좋습니다.

1. 설비/운전 이상

계량기는 정상인데, 실제 설비 운전 상태가 비정상인 경우

  • 부하가 비정상적으로 지속 증가
  • 야간/주말에도 꺼지지 않는 소비
  • 냉난방 계절과 맞지 않는 동작

2. 계량 채널/센서 이상

설비는 정상일 수 있으나 센서, meter channel, 내부 계산이 잘못된 경우

  • |PF| > 1
  • 갑작스런 단발 spike
  • redundant pair 간 불일치
  • 한 feature만 비정상이고 나머지는 정상

3. 데이터 수집/저장 품질 문제

실제 meter 값 이전에 DB/통신/집계 단계에서 깨지는 경우

  • 결측(gap)
  • 중복 timestamp
  • 갑작스런 0 입력
  • 시간축 밀림

프로젝트에서 자주 보는 패턴

패턴 가능성 높은 원인 설명
여러 관련 feature가 같이 변함 설비/운전 이상 P, I, qv, Tdiff가 함께 움직이면 실제 운전 변화일 가능성이 큼
한 feature만 단발적으로 물리 범위를 벗어남 계량/계산 이상 PF만 11로 튀고 P, U, I는 정상이라면 설비 이상보다 meter 채널 문제에 가까움
같은 위치 redundant pair 중 한쪽만 이상 계량 채널 이상 설비는 하나인데 meter 출력이 갈리므로 sensor/meter path 문제 가능성 증가
긴 결측 후 갑작스런 비정상값 통신/저장 품질 문제 gap과 recovery 과정에서 잘못 기록된 값일 수 있음

5. 단발성 이상치(single-point spike)는 어떻게 해석해야 하는가

사용자가 질문한 핵심은 “정상값이 쭉 나오다가 어느 한 시점에만 갑자기 PF=11이 튀는 경우를 어떻게 해석할 것인가”입니다.

실무 해석: 이런 패턴은 대체로 설비 고장의 전조라기보다 순간적 measurement fault, 계량기 내부 계산 오류, 통신/저장 오류로 해석하는 편이 더 타당합니다.

왜 설비 문제로 보기 어려운가

  • 전조 없이 단발적으로 튄다.
  • 지속성 있는 regime change가 없다.
  • 관련 feature들이 함께 이상을 보이지 않을 수 있다.
  • 물리적으로 불가능한 값 자체가 핵심이다.

왜 “순간적 계산/계량 오류”라고 보는가

  • 계량기는 일부 값을 내부에서 계산한다.
  • 특정 시점의 입력 조합이 깨지면 파생 feature만 튈 수 있다.
  • 센서가 완전히 죽은 것이 아니라도 순간 misread가 가능하다.
  • 한 시점 또는 하루 단위로만 튄다면 persistent hardware failure보다 transient fault에 가깝다.
따라서 권장 표현:
“이상치는 설비 고장의 징후라기보다, 해당 시점의 계량/계산 경로에서 발생한 순간적 measurement fault로 해석하는 것이 더 타당하다.”

6. H2.Z66 / H2.ZE66 같은 redundant pair는 어떻게 봐야 하는가

redundant pair는 이론적으로 같은 위치 또는 같은 전력 흐름을 중복 계량하는 쌍이므로, 큰 추세는 비슷해야 합니다. 하지만 실제로는 두 계량기가 완전히 같은 패턴을 보장하지는 않습니다.

상황 해석
두 meter 모두 비슷하게 움직임 정상적인 redundant pair 가능성 높음
한쪽만 |PF| > 1 설비보다 해당 계량 채널/계산 경로 문제 가능성 높음
한쪽은 full coverage, 다른 쪽은 후반기만 존재 교체/추가 계량기 가능성, 기간 비교 해석 주의
한쪽만 결측/0/stuck이 많음 하드웨어/통신 경로 불량 가능성

본 프로젝트에서는 H2.Z66는 main representative pattern용으로, H2.ZE66는 redundant pair 불일치 및 PF 이상치 사례용으로 쓰는 것이 자연스럽습니다.

8. 본 프로젝트 전처리/해석 기준에 연결하면

  • |PF| > 1은 물리적 이상치로 보고 NaN 또는 flag 대상
  • 음수 전류, 음수 소비전력, 0 이하 전압/주파수도 물리적 이상치로 우선 처리
  • 설비 이상 탐지는 “물리적으로 가능한 값이지만 비정상 패턴”을 대상으로 별도 해석
  • single-point impossible spike는 설비 fault보다 data quality / metering fault로 우선 분류
  • redundant pair 불일치는 설비 fault 판단보다 meter quality check에 먼저 사용

9. 요약

  • 계량기는 일부 값을 직접 측정하고, 일부 값을 내부에서 계산한다.
  • P, PF, Q, W는 계산 성격이 강하다.
  • |PF| > 1은 물리적으로 불가능하므로 설비 상태보다 meter/calculation fault를 우선 의심한다.
  • 단발 spike는 persistent hardware failure보다 transient measurement fault에 가깝다.
  • 월별 overlay는 패턴용, event zoom과 daily max/count는 이상치 강조용이다.
