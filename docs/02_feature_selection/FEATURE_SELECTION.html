Feature Selection — 상관계수 기반 대표 feature 선정

분석 방법

  • 전체 상관계수 HTML(plotly dashboard)에서 6year 기준 평균 절대 상관계수 |corr| 추출
  • 1 - |corr| 을 거리로 변환 후 Complete Linkage 계층 클러스터링 적용
  • Complete linkage: 클러스터 내 모든 쌍이 임계값을 만족해야 묶임 → 허브 문제 방지
  • 임계값: |corr| >= 0.7 (distance threshold = 0.3)
  • 전기: consumption(64개) / production(7개) 분리
  • 열: cooling(7개) / heating(2개) 분리

현재 구현 메모: 대표 상관분석/대시보드 스크립트에서는 feature 단순화를 위해 전기 f를 현재 제외하고 P, U1, PF만 사용함

Cooling vs Heating 핵심 차이

  • 냉방: P와 Tdiff 분리 (P↔Tdiff=0.386) → 독립적 이상 신호로 둘 다 유지
  • 난방: P와 Tdiff 묶임 (P↔Tdiff=0.744) → 상관 높으나 Tdiff가 이상탐지 직접 지표이므로 유지. Tvl만으로는 공급온도 상승 원인(공급측 이상 vs 환수온도 저하) 구분 불가

# Feature 의미 비고
1 P 열량 단독
2 qv 유량 단독
3 Tdiff 온도차(Tvl-Trl) P↔Tdiff=0.744로 묶이나 이상탐지 직접 신호로 유지

Tvl, Trl 제거 (냉난방 공통): Tdiff = Tvl - Trl로 두 온도의 차이를 직접 포착. Tvl 단독은 공급온도 상승 원인 구분 불가

Igm 제거 (냉난방 공통): 최대 0.33으로 낮음
Ua, Dc, Sc 제거 권장: 모든 내부 변수와 상관 낮고 물리적 해석 불명확

주의사항 및 한계점

1. 6year 평균 기반 분석

내용: 계절별·연도별 상관관계 변화를 반영하지 않고 6년 전체 평균값으로 클러스터링했음

감안 가능한 이유: 6년치 평균은 계절 편향이 상쇄되어 장기적으로 안정적인 관계를 나타냄. 단기 이상치나 특정 계절의 패턴보다 전반적인 구조적 관계 파악이 목적이므로 분석 목적에 부합함

2. 전체 계량기 평균 기반 클러스터링

내용: 개별 계량기마다 상관 구조가 다를 수 있으나, 전체 계량기의 평균 상관계수로 대표 feature를 선정했음

감안 가능한 이유: 전기는 consumption/production, 열은 cooling/heating으로 에너지 방향과 용도가 다른 그룹을 분리하여 분석했음. 개별 계량기 단위의 차이는 계량기 간 상관분석(다음 단계)에서 보완 예정

3. 건물·구역별 특성 미반영

내용: H1, H2, H3 등 건물/구역별로 설비 특성이 달라 상관 구조가 다를 수 있음

해결 방향: Plotly 상관계수 대시보드에서 계량기별로 직접 확인 가능. 대표 계량기 선정 단계에서 계량기 간 상관분석 시 건물별 패턴을 추가로 파악

4. PF2/PF3 정보 손실 가능성 (Consumption)

내용: Consumption 기준 PF1↔PF2=0.686, PF1↔PF3=0.680, PF2↔PF3=0.640으로 complete linkage 기준(0.7) 미달 → PF2/PF3가 별도 클러스터 분리

감안 가능한 이유: PF↔PF2=0.742, PF↔PF3=0.783으로 70% 이상 정보가 겹침. 실용적으로 PF가 대표성을 가지며, Production에서는 전부 하나로 묶임

5. 외부 변수 처리 원칙

전기 계량기: Ta↔P=0.190, Igm↔P=0.211로 전부 0.3 미만 → Ta, Igm 제거

열계량기: 냉난방 부하는 외기온도에 직접 영향받는 구조
- Ta: Cooling Ta↔P=0.453 / Heating Ta↔P=0.692 → Ta 유지
- Igm: 냉방 0.330, 난방 0.320 이하 → Igm 제거

6. 내부 변수 단독 feature 처리 원칙

  • 내부 변수가 다른 feature와 상관이 낮다 = 독립적 정보를 가진다는 의미 → 제거하지 않음
  • 외부 변수와 달리, 상관이 낮을수록 오히려 고유 신호일 가능성
  • Ua, Dc, Sc: 100% 계량기에 존재하나 물리적 의미 불명확 → 모델 학습 단계에서 검증 후 결정

7. 계량기별 컬럼 불일치

내용: 계량기마다 보유 컬럼이 다름 (예: Q는 44/71개, W1은 26/71개 계량기에만 존재)

처리 방법: 클러스터링 시 "해당 feature 쌍이 둘 다 존재하는 계량기에서만" 평균 계산 → 없는 컬럼은 자동 제외. 대표 feature(P, U1, PF, W)는 71개 전 계량기 보유 확인 완료. 예외: V.Z84에 PF, f 없음 → 해당 계량기 적용 시 결측 처리
