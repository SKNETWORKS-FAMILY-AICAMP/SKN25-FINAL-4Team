## 3. forecast.py 수정 사항

### train/validation/test 3분할 구조로 변경

**변경 이유**  
기존 구조는 2018~2021 전체를 train으로 사용하고 2022~2023을 test로 사용해서 validation이 없었음.  
2022~2023을 한 번도 보지 않은 진짜 live 데이터로 평가하기 위해 3분할 구조로 변경.

**분할 기준**

| 구간 | 기간 | 행수 |
|------|------|------|
| train | 2018-01-08 ~ 2020-12-31 | 104,426행 |
| validation | 2021-01-01 ~ 2021-12-31 | 34,540행 |
| test (live replay) | 2022-01-01 ~ 2023-12-31 | 69,988행 |

**추가된 함수**  
train_val_test_split_temporal: train/validation/test 3분할 함수

**모델별 validation 활용**

| 모델 | validation 활용 방식 |
|------|-------------------|
| XGBoost | eval_set을 validation으로 변경 (조기 종료 기준) |
| RF | 인자만 추가, 내부 로직 변화 없음 |
| Prophet | 인자만 추가, 내부 로직 변화 없음 |
| SVR | 인자만 추가, 내부 로직 변화 없음 |
| SARIMAX | 인자만 추가, 내부 로직 변화 없음 (RunPod 전용) |

## 4. 모델 실험 결과

**H1.W11 P값 기준, 15min 해상도**

### 구조 변경 전 (2018~2021 train, 2022~2023 test)

| 모델 | MAE | RMSE | MAPE |
|------|-----|------|------|
| RF | 2,833 | 5,436 | 393% |
| XGBoost | 3,905 | 8,098 | 891% |
| SVR | 14,811 | 26,189 | 64,500% |
| Prophet | 94,170 | 120,793 | 17,011% |

### 구조 변경 후 (2018~2020 train, 2021 validation, 2022~2023 test)

| 모델 | MAE | RMSE | MAPE |
|------|-----|------|------|
| **RF** | **3,971** | **8,207** | **551%** |
| XGBoost | 4,423 | 8,966 | 550% |
| SVR | 14,757 | 25,966 | 65,504% |
| Prophet | 497,801 | 528,621 | 1,119,927% |

**챔피언 모델: RF**

성능 저하 이유: train 데이터가 4년에서 3년으로 줄면서 전반적으로 성능 감소. 단, 2022~2023을 한 번도 보지 않은 상태에서 평가한 것이므로 더 정직한 수치.
