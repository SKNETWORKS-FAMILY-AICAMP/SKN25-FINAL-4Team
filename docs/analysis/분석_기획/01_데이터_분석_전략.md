# EMS 데이터 분석 전략

이 데이터의 핵심 특성 3가지 — **인공 보정값 혼재**, **결측 잔존**, **설비 변경에 따른 분포 변화** — 를 감안한 분석 전략.

---

## 1. 처리 단계별 용도를 명확히 분리한다

같은 센서의 같은 시간 데이터가 4가지 버전으로 존재한다. **목적에 따라 다른 버전을 써야 한다.**

```
┌─────────────────────────────────────────────────────────┐
│                    분석 목적별 데이터 선택               │
├─────────────────────┬───────────────────────────────────┤
│  예측 / 트렌드 분석  │  corrected_resampled (15min, 1h) │
│  보고 지표 산출      │  corrected_resampled (1h)        │
│  이상 탐지 모델 학습 │  raw + labeled issues (YAML)     │
│  이상 탐지 모델 평가 │  raw (오류 그대로) vs corrected   │
│  데이터 품질 감사    │  raw ↔ corrected 비교            │
│  계층적 무결성 검증  │  corrected_resampled             │
└─────────────────────┴───────────────────────────────────┘
```

> [!IMPORTANT]
> 현재 `01_eda.ipynb`는 `cr_measurement_1h` (corrected_resampled)만 사용 중이다. 이상 탐지를 위해서는 `full_measurement`에서 `processing_level = 'raw'`를 조회하거나, 원천 YAML 라벨 파일을 DB에 적재하는 작업이 선행되어야 한다.

## 2. 시간을 설비 이벤트 기준으로 나눈다 (Regime Segmentation)

이 데이터의 **가장 까다로운 특성**이다. 6년 동안 설비 구성이 여러 번 바뀌었기 때문에, 2018년 패턴으로 2023년을 예측하면 틀린다. 전체 기간을 아래 이벤트 기준으로 **구간(Regime)** 으로 나누어야 한다.

```
2018.01 ──────── 2019.02 ── 2019.06 ── 2020.03 ── 2020.06 ── 2020.09 ── 2023.06 ── 2023.12
   │                │          │          │          │          │          │          │
   ▼                ▼          ▼          ▼          ▼          ▼          ▼          ▼
 초기 운영      CHP 로직    PV 1차     COVID      PV 2차    계량기      난방       데이터
 (PV 없음,     업데이트     설치       시작       증설      교체       현대화      종료
  CHP On/Off)  (50-100%    (소규모)              (풀용량)  (H2.Z35    (CHP
               모듈레이션)                                 →Z351)    가동률↑)
```

### 분석에 미치는 영향

| 구간 변화 | 영향받는 측정항목 | 분석 시 처리 |
|---|---|---|
| PV 설치 전 (~2019.06) | PV 발전량, 역송전, WQ_out | 이 기간의 PV 관련 데이터는 0 또는 부재. **학습 제외하거나 별도 모델** |
| PV 증설 (2020.06) | PV 발전량 스케일 변화 | 증설 전후 데이터를 같은 분포로 가정하면 안 됨 |
| CHP 로직 변경 (2019.02) | CHP 전기/열 생산 패턴 | On/Off → 연속 모듈레이션. **시계열 분포 자체가 바뀜** |
| COVID (2020.03~) | 사무실 전력, 냉난방 부하 | 재택근무로 인한 부하 급감. **달력 피처만으로는 설명 불가** |
| 계량기 교체 (2020.09) | H2.Z35/36 → H2.Z351/361 | **6일 결측 + URN 변경**. 연속 시계열로 이어 붙이는 전처리 필요 |

### 권장 접근법

- **예측 모델**: 가장 안정적인 최근 구간(2020.06 ~ 2023.06)을 주 학습 구간으로 사용. 이전 구간은 보조 학습 또는 제외
- **이상 탐지**: 설비 변경 자체를 이상으로 오탐하지 않도록, 각 Regime 내에서 별도 baseline 구축
- **트렌드 분석**: Regime 경계를 주석(annotation)으로 표시하여 보고서에서 분포 변화의 원인을 설명

## 3. 결측 처리 전략을 유형별로 다르게 적용한다

`corrected_resampled`에도 **3가지 종류의 결측**이 남아있다. 각각 다른 방식으로 처리해야 한다.

### 유형 A: 기상 데이터 결측 (Weather Station)
- **원인**: 기상 관측소 하드웨어 반복 고장
- **특성**: 수 시간~수 일 단위로 빈번하게 발생
- **보정 방식**: 논문이 직접 권장한 **독일 기상청(DWD) Station 07341** 데이터로 대체
- **구현**: DWD CDC API에서 Ta, Igc 등을 가져와 기상 결측 구간에 merge

### 유형 B: 게이트웨이 장애 결측 (대규모 Gap)
- **원인**: 특정 구역의 데이터 수집 게이트웨이 하드웨어 고장
- **특성**: 3주~2개월 단위. 해당 구역의 **모든 계량기가 동시에** 결측
- **보정 방식**:
  - 상위/하위 계량기 관계를 이용한 교차 추정 (예: 전체 소비 - 다른 구역 합 = 해당 구역 추정)
  - 또는 해당 구간을 분석에서 **제외**하고, 모델 학습 시 해당 기간을 마스킹

### 유형 C: 인공 보정 데이터 (Clone Gap Filling으로 채워진 구간)
- **원인**: corrected 단계에서 과거 데이터를 복사해 채운 것
- **특성**: 겉보기에는 정상이지만, **실제 측정값이 아닌 인공 생성 데이터**
- **위험**: 이 구간을 모델이 학습하면 "과거 패턴 반복"에 편향(bias)
- **보정 방식**:
  - raw와 corrected를 비교하여 인공 데이터 구간을 식별 (raw에서 NULL인데 corrected에서 값이 있는 구간)
  - 해당 구간에 `is_synthetic = True` 플래그를 달아서, 모델 학습 시 **가중치를 낮추거나 제외**

## 4. 계층적 미터 관계를 교차 검증에 활용한다

논문의 Figure 1에 나오는 미터 트리 구조를 활용하면, 데이터의 물리적 무결성을 검증할 수 있다. 온톨로지(`docs/ontology/ems.ttl`)가 이 관계를 이미 정의하고 있다.

### 검증 원리

```
상위 미터 측정값 ≈ 하위 미터들의 합
```

예시:
```
Grid In (V.Z81 + V.Z82) + CHP (H1.Z20) + PV ≈ 전체 소비
전체 소비 ≈ Office + Workshop + Emission Lab + Cooling + Ventilation + Others
```

### 활용 방법

1. **데이터 품질 모니터링**: 상위-하위 차이가 특정 임계치를 넘으면 센서 이상 경고
2. **결측 구간 추정**: 하위 미터 중 하나만 결측이면 `상위 - 나머지 하위 합`으로 추정 가능
3. **이상 탐지 보조 피처**: `상위 - 하위 합`의 잔차(residual) 자체가 이상 탐지 입력이 됨

## 요약: 핵심 3원칙

1. **목적에 따라 다른 처리 단계의 데이터를 쓴다** — corrected_resampled가 만능이 아님
2. **6년을 하나의 덩어리로 보지 않는다** — 설비 변경 기준으로 Regime을 나눈다
3. **센서 하나만 보지 않는다** — 계층적 미터 관계로 교차 검증한다
