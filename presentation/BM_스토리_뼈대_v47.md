## 1. 왜 했냐 (문제 정의)

**팩트 1: 에너지 비용은 제조 중소기업의 실질적 부담**
- 산업용 전기요금 2000년 이후 2024년까지 227% 인상, 2023년 산업용이 주택용 역전 [^0]
- 최근 3년 사이 7차례 인상으로 약 80% 급등 — 미국·중국 등 경쟁국보다 40~50% 높은 수준 [^0b]
- 제조 중소기업 95%가 전기요금 부담을 느끼며, 70%는 특별한 대책이 없는 상황 (n=309개사) [^0c]
- 제조업 10곳 중 4곳이 전기요금 부담으로 대체 전력조달 방식 검토 중 [^0]
- 2026년 4월부터 시간대별 전기요금 개편 시행 — 저녁 18~21시 최고요금, 주말 낮 50% 할인 구조로 변경. 피크 관리 못 하면 요금 부담이 더 커지는 구조 [^15]
- ESG, CBAM 등 탄소 관련 규제가 강화되는 추세 — 2026년부터 본격 시행 [^1]

**팩트 2: FEMS·CMS 도입률이 낮음**
- FEMS: "11만 제조기업 중 97%는 중소기업으로 FEMS 도입에 비용부담의 어려움을 가지고 있습니다." [^2]
- 산업통상자원부: 중소기업 FEMS 보급 저조 문제 해결을 위해 244억원 투입해 K-FEMS 표준 플랫폼 개발 (2020~2024) — 정부가 직접 나설 만큼 민간 보급이 안 됐다는 방증 [^3]
- 국내 스마트공장 3만 144개 구축됐지만 약 75% 이상이 기초 단계에 머물러 있어 고도화 지연 중 [^14]
- CMS: FEMS 도입에도 비용부담을 느끼는 중소기업이 97%인 상황에서 진동·전류 센서 별도 설치가 필요한 CMS를 추가로 도입하는 것은 현실적으로 어려움 — 중소기업 관점에서 도입 장벽이 높음

**팩트 3: 도입해도 문제가 있음**
- 기존 FEMS는 통계 기반 상관관계 분석을 제공하지만 AI 기반 원인 추정 및 정비 의사결정 지원 기능은 없음 [^4]
- 기존 FEMS는 과거/현재 데이터 분석에만 치중 — 실시간 피크 감지 및 대응 기능 없음 [^4]
- 기존 CMS는 진동·전류 센서 별도 설치 및 독립 시스템 구축 필요 — 설비가 늘수록 관리 복잡도가 함께 증가 [^17]
- FEMS와 CMS가 별개 시스템으로 운영 — 에너지 이상과 설비 이상을 연결해서 보는 통합 인사이트 없음

| 연구 단계 | ETRI 업종맞춤형 | ✅ | — | ✅ | 2026.03 성과 발표, 상용화 전 — 에너지다소비 대형 업종 전용(바이오·의약, 식품, 금속·유리, 제지), 중소기업 범용 아님. 향후 확장 시에도 1단계 바우처를 통해 중소기업 레퍼런스와 구독 기반을 먼저 만들어가는 것이 전략의 핵심 |
| **우리** | **TTF-FMS** | **✅** | **✅** | **✅** | |

**핵심 공백**: 공개 확인 가능한 경쟁사 자료 기준으로는, 설비 상태 감시 → 이상 탐지 → 원인 분석 → 작업지시 생성 → 자연어 질의를 하나의 워크플로우로 통합 제공하는 사례를 확인하기 어려웠습니다. 공개 자료에 포함되지 않은 기능이 존재할 가능성은 배제하지 않습니다.

**CMS 영역 비교**

| 구분 | 업체 | 데이터 소스 | 이상 감지 수준 | 추가 센서 필요 |
|------|------|------|------|:---:|
| 상용 CMS | 한국네트웍스 Pi-CMS | 진동 센서 | 이상 유형 분류 + 알람 | ✅ |
| 상용 CMS | 원프레딕트 가디원 모터 | 전류 센서 | 모터 상태 이상 여부 + 알람 | ✅ |
| **우리** | **TTF-FMS** | **기존 전력 계량기** | **전력 패턴 기반 이상 징후 선별 + 원인 추정** | **❌** |

→ 기존 CMS는 추가 센서 설치가 필요하지만 우리는 이미 공장에 설치된 전력 계량기 데이터만으로 설비 이상 징후를 감지함. 추가 투자 없이 FEMS + CMS Lite 기능을 동시에 제공하는 하이브리드 플랫폼.

**전력 데이터로 설비 이상 징후 선별이 가능한 원리**

전력 데이터만으로 모든 설비 고장을 직접 진단할 수 있다는 의미는 아닙니다. 다만 설비 상태 변화는 전력 패턴 변화로 나타나며, 아래 운영 이상 유형은 전력 데이터만으로도 탐지 가능합니다. TTF-FMS는 정밀 진단 이전 단계에서 이상 징후를 선별하고 대응 우선순위를 제공하는 역할을 수행합니다.

- PowerSpike: 유효전력이 평소 대비 급격히 증가하는 패턴에서 탐지
- CHPOutage: 열병합발전 계량기 출력이 갑자기 0으로 떨어지는 패턴에서 탐지
- NightConsumption: 비조업 시간대 전력 소비가 감지되는 패턴에서 탐지

→ 설비 상태는 전력 데이터에 고스란히 반영되며, Honda R&D Europe 6년치 실측 데이터([^5])에서 이 이상 유형들이 분류 태스크로 구성됨

**기존 상용화된 FEMS 플랫폼의 한계 원인**
- 개발 시점(2020~2022년) 문제 — AI·LLM의 산업 본격 접목 이전 시대
- 데이터 부족 — "such data is only sparsely available" [^5]

**기존 상용화된 CMS 플랫폼의 한계 원인**
- 진동 센서 별도 설치 필요 — 기존 진동 센서 방식 대비 전류 센서 방식도 구축 비용 80~90% 절감 가능하나 [^17], 우리는 센서 자체가 불필요
- 설비별 맞춤 설치 구조 — 표준화 어렵고 중소기업 전담 인력 부족
- FEMS와 별개 시스템으로 운영 — 에너지 이상과 설비 이상을 연결해서 보는 통합 인사이트 없음

**왜 FEMS+CMS 하이브리드가 지금까지 없었나**

세 가지 구조적 이유가 복합적으로 작용했습니다.

1. **기술적 이유** — 전력 데이터만으로 설비 상태를 진단한다는 발상은 AI 발전 이후에야 가능해졌습니다. 고품질 실세계 에너지 데이터 자체가 희귀했고 [^5], 전류 기반 설비 진단 제품(원프레딕트 가디원 모터)조차 2022년에야 출시됐습니다 [^17].
2. **시장 구조 이유** — FEMS 기업은 에너지 도메인 전문, CMS 기업은 설비 진단 도메인 전문으로 서로 다른 영역이라 통합할 동기가 없었습니다. 제조데이터·AI 관련 전담 부서와 인력을 보유한 기업은 전체의 0.8%에 불과한 상황에서 두 영역을 동시에 다루는 역량을 갖춘 기업이 없었습니다 [^18].
3. **중소기업 타깃 이유** — FEMS 도입에 비용부담을 느끼는 중소기업이 97%인 상황에서 [^2], CMS까지 별도로 도입하는 건 현실적으로 불가능했습니다. 두 시스템을 하나로 통합해서 중소기업 대상으로 만든다는 발상 자체가 없었던 겁니다.

→ AI가 전력 데이터에서 설비 이상 패턴을 잡아낼 수 있게 되면서, 하나의 데이터 소스로 두 기능을 동시에 구현하는 상용화 접근이 가능해졌습니다.

**우리 플랫폼의 데이터 기반**
- Nature Scientific Data 2025년 게재 Honda R&D Europe 6년치 데이터셋 활용 [^5]

**외부 검증 완료**
- AI Hub 국내 제조설비(펌프/일반모터 73개 설비) 데이터로 전이 검증 완료 [^6] → 7-5절 참고

## 4. 우리 솔루션이 주는 것 (차별점)

| 기존 플랫폼 | 우리 플랫폼 (TTF-FMS) |
|-----------|------------|
| 통계 기반 상관관계 분석 제공 | LLM 기반 원인 추정 및 정비 의사결정 지원 — 전기 시그니처 근거로 설명 (FEMS+CMS) |
| 이상 발생 후 사후 대응 중심 | COP·이상 발생률 추세 분석으로 "현 추세면 N개월 후 기준치 도달" 위험 사전 예측 — 예지보전 지원 (CMS) |
| 과거 데이터 원인·결과 분석에 중점 | 전력 수요 패턴을 분석해 월말 요금 추정 및 피크 위험 모니터링 (FEMS) |
| 챗봇 없음 — 대시보드 조회만 가능 | 자연어 챗봇으로 설비 상태 조회·원인 추정·작업지시 생성·운영 권고·정비 이력 조회까지 Agent 수준 지원 (FEMS+CMS) |
| 진동·전류 센서 추가 설치 필요 | 기존 전력 계량기만으로 설비 이상 징후 선별(Screening) — 추가 투자 없음 (CMS Lite) |
| 단순 템플릿 리포트 수준 | AI가 자급률·COP·그리드 의존도·외기온 상관관계를 분석해 월간 보고서 자동 생성 (FEMS) |

**TTF-FMS는 단순 모니터링 도구가 아닌 설비 운영 AI Copilot입니다.**

현장 담당자가 이상을 인지한 순간부터 정비가 완료될 때까지 전 과정을 AI가 지원합니다:

```
이상 탐지 → 원인 추정 → 작업지시 생성 → 작업 진행 관리 → 정비 이력 누적
     ↑                                                           ↓
     └──────────────── 적응형 학습으로 권고 품질 지속 개선 ────────┘
```

**도입 시나리오 비교 (CMS Lite)**

기존 CMS 도입 시:
```
1. 진동/전류 센서 구매 및 설치
2. 설비별 맞춤 설치 작업 (수일 소요)
3. 데이터 수집 인프라 별도 구축
4. 그제야 설비 이상 징후 감지 시작
```

우리 플랫폼:
```
1. 이미 설치된 전력 계량기 데이터 연결
2. 즉시 이상 징후 탐지 및 유형 분류
   → PowerSpike / COPDrop / CHPOutage / NightConsumption / PVNightNonZero 등 LLM 기반 해석
3. LLM 기반 원인 추정 및 정비 가이드 생성
```
→ 추가 하드웨어 투자 없이 계량기 연동 설정 완료 시 당일 운영 시작 가능 (스마트공장 1~2단계 완료로 데이터 수집 인프라가 이미 구축된 기업 기준)

**기능 예시**

이상 원인 추정 + 설비 정비 의사결정 지원 (FEMS+CMS 동시 커버) — 이상탐지 → AI 분석 → 작업지시 흐름:
```
🚨 이상 탐지
냉방설비 · COPDrop HIGH · 최근 30일 5건
대표 발생: 2023-07-15 14:00

🤖 AI 분석
최근 30일 동안 냉방설비에서 냉방 효율 저하 패턴이
반복적으로 관찰되었습니다.
COP가 정상 범위 대비 지속적으로 낮게 유지되고 있으며,
냉각수 계통 또는 냉방설비 운전 상태 점검이 필요합니다.

추정 원인
· COP 하락 구간이 외기온 상승 시점과 일치 → 냉각 부하 과다 가능성
· 냉각수 순환 계통 이상 또는 응축기 오염 여부 점검 권고

📋 작업지시 생성
작업명: 냉방설비 점검
우선순위: HIGH
권고 사항:
· 냉각수 순환 상태 확인
· 응축기 오염 여부 점검
· 최근 COP 추세 모니터링

📈 정비 이력
최근 3개월 동일 유형 이상: 5건
최근 조치: 냉각수 펌프 점검 완료
현재 상태: 경과 관찰 중
```

목표 요금 관리 (FEMS):
```
📊 AI 비용 분석·권고

이번 달 목표 요금: ₩5,000,000
현재까지 누적: ₩3,920,000 (196,000 kWh · 28/31일)
AI 예상 최종 요금: ₩4,650,000 (▼7.0% vs 목표)
상태: 정상 — 피크 위험 낮음

권고:
· 현재 사용 패턴 유지 시 목표 요금 내 운영 가능
· 피크 시간대(18~21시) 설비 동시 가동 주의

```

## 5. 수익화 로드맵 (3단계)

**1단계: 도입기 — 정부 바우처 기반 초기 레퍼런스 및 실증 데이터 확보**

정부 지원사업은 단순 매출 확보 수단이 아니라 초기 레퍼런스 확보 전략입니다. 초기 도입 기업에서 확보한 에너지 절감 효과, 설비 이상 탐지 사례, 정비 이력은 이후 스마트공장 사업 및 SaaS 구독 전환의 핵심 근거가 됩니다.

- **과기부 · NIPA: 2026년도 중소기업 클라우드 서비스 보급·확산 사업** [^8]
  - 수요기업 자부담 20%, 정부 75% + 공급기업 5% 지원 구조, 공급기업 통장으로 직접 정산
  - AI 융합 SaaS 플랫폼은 공급기업 Pool 등록 심사 통과 시 참여 가능
- **과기부 · NIPA: 2026년도 AI 바우처 지원사업** [^9]
  - 수요기업(중소기업)에 AI 솔루션 구매 바우처 최대 2억원 지급, 공급기업에 판매 대금 직접 정산
  - 총 130건 지원 (건수 제한 있음), 공급기업 Pool 등록 후 수요기업과 매칭

### 7-1. 수요 예측 모델 — v84 앙상블 (1시간 단위)

**모델 구성**
- 앙상블: LSTM(×7) + CatBoost + LightGBM + Ridge + Seasonal Naive
- 예측 타겟: 잔차 P(t)−P(t-1) (변화량 예측 후 anchor 복원)
- 개인화: 45개 계량기 각각 별도 학습
- 예측 horizon: 1h / 3h

**성능 지표 (전체 45개 계량기 중앙값 기준)**

| 지표 | 1h | 3h |
|------|:---:|:---:|
| MAPE (중앙값) | **50.2%** | **75.2%** |
| RMSE (중앙값) | **1,147.9** | **1,431.4** |
| beats_persistence | **27/45** | **16/45** |

※ MAPE 중앙값은 H1.Z19, H1.Z23, H3.Z48, H1.K11 등 near-zero 계량기(실제값이 0에 근접해 MAPE 분모가 작음) 포함 수치. electric 그룹 제외 시 1h 중앙값 약 17~20% 수준.
※ beats_persistence는 EXPERIMENT_SUMMARY 기준 (45개 직접학습 계량기 대상).

**지표 정의**

| 지표 | 수식 | 해석 | 한계 |
|------|------|------|------|
| MAPE | mean(\|actual−pred\|/\|actual\|)×100 | 실제값 대비 예측 오차 비율(%). 낮을수록 좋음 | actual≈0인 계량기에서 분모가 작아 수치가 폭발적으로 커짐. near-zero 계량기 포함 시 중앙값이 과대평가됨 |
| RMSE | √(mean((actual−pred)²)) | 오차를 제곱해 평균낸 뒤 루트. 큰 오차에 더 민감. 단위는 원본과 동일(kW) | 스케일에 따라 절대값 해석이 달라짐. 계량기 간 직접 비교에 부적합 |
| beats_persistence | (persistence_RMSE−model_RMSE)/persistence_RMSE×100 | 직전값 반복 기준선 대비 RMSE 개선율(%). 양수면 baseline보다 나음 | 기준선(persistence)이 이미 좋은 계량기에서는 개선 여지가 작아 보임 |

**패턴 학습 검증 (발표 방어 근거)**

잔차 타겟이 단순히 P(t-1) persistence에 의존하지 않고 실제 패턴을 학습했음을 3가지 근거로 검증.

근거 1 — Feature Importance

| 모델 | test6 P(t−1) 중요도 | residual P(t−1) 중요도 | 해석 |
|------|:---:|:---:|------|
| CatBoost | 50.0% | 20.3% (41/45 감소) | persistence 의존 탈피 |
| LightGBM | 69.1% | 17.3% (44/45 감소) | persistence 의존 탈피 |
| 시간 피처 (LightGBM) | 2.95% | 17.4% (45/45 증가) | 패턴 학습 강화 |

근거 2 — 잔차 ACF (자기상관 감소)

| 항목 | test6 | residual |
|------|:---:|:---:|
| 평균 잔차 lag-1 ACF | 0.219 | **0.085** |
| ACF 감소한 계량기 | — | 29/45 |

모델 예측 후 남은 자기상관이 절반 이하로 감소 → 잔차의 autocorrelation 구조 포착 성공.

근거 3 — 중간 모델 beats_persistence

| 모델 | test6 | residual |
|------|:---:|:---:|
| LSTM v1~v7 | 33~42% | **91~98%** |
| CatBoost | 42% | **100%** |
| LightGBM | 40% | **100%** |
| Ridge | 29% | **89%** |

※ 중간 모델(개별 모델) 기준 수치로 최종 앙상블 beats_persistence(27/45)와 다름. 앙상블 이전 단계에서 잔차 타겟의 패턴 학습 효과를 확인한 근거.

### 7-3. 이상탐지 성능

**탐지 구조**
- 주력: 잔차 기반 이상탐지 + IsolationForest 보조 검증
  - 잔차(|실제−예측|) 임계 초과 시 이상 후보 → IsolationForest로 보조 검증
  - 둘 다 = HIGH / 잔차 1.5배 = MEDIUM / 한쪽만 = LOW
- 폴백: 통계(Z·IQR·STL) + IsolationForest + LSTM-AE 3단 투표
  - 2표 이상 = HIGH / 1표 = MEDIUM

**이상 유형 분류 구조**

v84는 잔차 기반 이상탐지 모델로 이상후보(경보 여부)만 판단합니다. PowerSpike/COPDrop 등 운영 관점 유형 분류는 LLM 에이전트가 담당합니다.

```
v84 예측 잔차
→ threshold 초과 여부 판단 (이상후보)
→ anomaly_agent
→ 센서값(grid_P, pv_P, chp_P, COP, 외기온) + ANOMALY_DOMAIN_PROMPT
→ LLM
→ PowerSpike / COPDrop / NightConsumption / CHPOutage / PVNightNonZero 해석
```

| 이상 유형 | 설명 | 탐지 원리 |
|-----------|------|-----------|
| PowerSpike | 유효전력 급등 | 잔차 급증 → LLM 해석 |
| COPDrop | 냉방효율 급락 | 잔차 급증 + COP 저하 → LLM 해석 |
| CHPOutage | 열병합발전 정지 | chp_P 급락 패턴 → LLM 해석 |
| NightConsumption | 비조업 시간대 전력 소비 | 야간 잔차 초과 → LLM 해석 |
| PVNightNonZero | 야간 태양광 비정상 출력 | pv_P > 0 야간 패턴 → LLM 해석 |

※ 유형별 탐지율은 정답 레이블 없어 정량 측정 불가. v84 성능 지표는 경보율/오탐율 기준으로 평가.

베이스 모델: EXAONE 3.5:7.8B (fast 모드, 의도분류·속도 경로) + Gemma4:12B (quality 모드, 보고서·진단)
평가 방식: gpt-5.5-as-Judge, 33문항, 5축(한국어·형식·근거성·논리성·실용성) 10점 척도

| 지표 | 초기 (Qwen 기준) | 최적화 후 (v8, Gemma4) | 비고 |
|------|:---:|:---:|:---:|
| 종합 평가 점수 | 2.4/10 | **8.6/10** | gpt-5.5 심사 기준 |
| 오프토픽 거절 정확도 | 5.0/10 | **9.0+/10** | |
| 보고서 형식 준수 | 6.0/10 | **10.0/10** | |
| 의도 분류 레이턴시 | 5,982ms | **~3,700ms** | keep_alive 최적화 후 |

※ gpt-5.5(8.9/10) 대비 근접 수준을 온프레미스 환경에서 구현.
※ 버그 9건 수정, 프롬프트 엔지니어링 9종 적용 결과.
※ Qwen2.5는 복잡한 수치 추론 시 중국어 전환(논리성·실용성 0점)으로 비채택.
※ gpt-5.5-as-Judge는 근거성 평가에 엄격 — 제공되지 않은 수치 생성 시 즉시 감점. gpt-4o 대비 전반적으로 1.0점 낮게 측정되나 모델 간 상대 순위 동일.

**아키텍처**
- 듀얼 모델: EXAONE(fast, max_tokens=10, 의도분류) + Gemma4:12B(quality, thinking 활성화, 보고서·진단)
- RAG: pgvector 코사인 유사도 기반, Top-K=5, 임계값=0.7. 실패 시 DOMAIN_KNOWLEDGE_PROMPT fallback
- 3중 오프토픽 방어: 키워드 룰 → LLM 폴백 → RAG Agent 내 거절 지시
- Critic 노드: 에너지 도메인 용어 8개 패턴 자동 교정 (예: 한전→독일 공공 전력망)

**지표 정의**

| 지표 | 수식 | 해석 | 한계 |
|------|------|------|------|
| 의도 분류 정확도 | TP_전체/N×100 | 골든셋 질문 중 올바른 에이전트로 라우팅된 비율(%). 높을수록 좋음 | 골든셋 100문항 기준으로 실제 사용 패턴과 분포가 다를 수 있음 |
| ROUGE-L (sLLM) | LCS(pred,ref)/len(ref) | 정답과의 최장 공통 부분열 기반 유사도. 문장 구조 일치도 반영 | 의미가 같아도 표현이 다르면 낮게 나옴 |
| BERTScore (sLLM) | cosine_sim(BERT(pred),BERT(ref)) | 임베딩 기반 의미 유사도. 표현 차이에 덜 민감 | 모델·언어 설정에 따라 절대값 해석이 달라짐. 단독 사용보다 ROUGE-L과 함께 해석 권장 |

## 9. 발표 스크립트 준비 항목 (구두 답변)

**A-1. Honda 데이터 국내 적용 가능성**
> "Honda R&D Europe은 유럽 연구개발 시설이고 저희 타깃은 국내 중소 제조공장으로 설비 구성과 가동 패턴이 다를 수 있습니다. 이 점을 검증하기 위해 AI Hub 국내 펌프/일반모터 73개 설비 데이터로 전이 테스트를 진행했습니다. AI Hub 데이터셋은 국내 63개 업체, 461개 설비에서 Mobile Energy Meter로 직접 계측한 국내 중소 제조 현장 실측 데이터로, 레티그리드 등 국내 기업이 현장에서 수집한 데이터입니다. 국내 중소 제조 현장의 특성을 반영한 외부 검증 데이터로 활용했습니다. Import P-Max는 AI Hub 데이터로 재학습 시 유효 설비 85%에서 Persistence 대비 개선됐고 중앙값 RMSE 개선율 17.5%로 Honda 결과(11~18%)와 유사한 범위가 나왔습니다. v84 앙상블 예측은 Honda 가중치 그대로 56개 설비 중 59%에서 개선됐습니다. 다만 실제 서비스에서는 고객사 데이터로 재학습하여 사용하며, 이것이 플랫폼의 개인화 학습 설계와 일치합니다. 이상탐지는 재학습 후 경보율 20.04%로 Honda 운영 수준(17.79%)에 근접했고, 오탐율도 31.10%에서 11.77%로 대폭 감소했습니다. 두 모델 모두 국내 데이터에서 파이프라인 구조의 전이 가능성을 확인했습니다."

**A-2. 전력 데이터로 설비 이상 징후 선별이 가능한 이유**
> "설비 이상은 반드시 전력 패턴 변화를 동반합니다. PowerSpike는 유효전력이 평소 대비 급격히 증가하는 패턴에서, CHPOutage는 열병합발전 계량기의 출력이 갑자기 0으로 떨어지는 패턴에서, NightConsumption은 비조업 시간대에 전력 소비가 감지되는 패턴에서 각각 탐지됩니다. 다만 저희는 모든 설비 고장을 직접 진단한다고 주장하지 않습니다. 정밀 진단 이전 단계에서 이상 징후를 선별하고, 현장 담당자가 우선순위를 잡을 수 있도록 지원하는 것이 역할입니다."

**A-3. 계량기 이상과 설비 이상의 연결 고리**
> "역률 저하는 설비가 무효전력을 과도하게 소비하고 있다는 신호입니다. 모터 과부하, 권선 열화, 콘덴서 불량 등의 상황에서 역률이 정상 범위(0.9 이상)를 이탈합니다. 전력 계량기가 이 신호를 잡아내고, 원인 추정 기능을 통해 설비 점검 근거를 제시합니다."

**C-1. 챗봇이 핵심 기능인 이유**
> "챗봇은 편의 기능이 아닙니다. 제조 현장 에너지 담당자는 SQL이나 대시보드를 다루지 않습니다. 자연어 질의가 데이터에 접근하는 유일한 인터페이스입니다. '이번 달 전기요금 왜 많이 나왔냐'는 질문에 바로 답하고, '열병합발전 작업지시 만들어줘'라는 요청에 실제로 작업지시를 생성하는 플랫폼이 현장에서 실제로 쓰이는 플랫폼입니다."

**C-2. 2단계 Pool 등록에 레퍼런스가 몇 건 필요한가**
> "탄소중립형 스마트공장 보급사업 공급기업 Pool 등록의 최소 실적 요건은 현재 확인 중입니다. 1단계 바우처를 통해 확보한 레퍼런스가 2단계 선정 평가에서 유리하게 작용한다는 구조적 논리는 맞으나, 몇 건이 필요한지 구체적 수치는 공고 확인 후 보완하겠습니다. 발표 전까지 공고를 재확인하겠습니다."

**C-3. 신생 기업이 바로 공급기업 등록 가능한가**
> "현재는 공급기업 등록 자체보다 초기 레퍼런스 확보가 우선 과제입니다. 정부 바우처 사업을 통해 확보한 실제 도입 사례와 운영 성과를 기반으로 공급기업 등록 경쟁력을 확보하는 전략입니다."

**D-1. 경쟁사 조사 기준**
> "경쟁사 비교는 각 업체 공식 홈페이지 및 공개 자료 기준으로 조사한 결과입니다. 공개 확인 가능한 범위 내에서 기능 유무를 판단했으며, 비공개 기능이 존재할 가능성을 배제하지는 않습니다."

**D-2. 경쟁사에도 AI 있는 것 아니냐**
> "가능성은 있습니다. 저희 분석은 공개 홈페이지, 브로셔, 제품 소개 자료 기준으로 수행했습니다. 공개 확인 가능한 범위에서는 원인 분석 지원, 작업지시 생성, 자연어 질의를 통합 제공하는 사례를 확인하지 못했습니다. 만약 유사한 기능 조합이 이미 시장에 있다면, 오히려 그 방향이 시장에서 인정받는다는 근거이므로 저희 방향이 맞다는 증거가 됩니다."

**D-3. LLM 환각 대응**
> "챗봇은 질문 의도를 분류해 5개 에이전트로 라우팅하는 구조입니다. 설비 상태·진단 질문은 CMS Agent가 DB를 직접 조회해 답변하고, 도메인 개념 질문은 RAG Agent가 도메인 지식과 벡터 검색을 결합해 답변합니다. LLM이 임의로 수치를 생성하는 구조가 아니며, 데이터 범위 외 질의에는 모른다고 응답하도록 설계되어 있습니다."

**D-4. 바우처-Pool 연결 경로**
> "바우처로 플랫폼을 도입한 기업은 에너지 절감 성과와 도입 사례가 생기고, 이것이 탄소중립형 스마트공장 보급사업 수요기업 신청 시 실질적인 근거가 됩니다. 해당 사업의 수요기업 요건은 탄소중립 스마트공장 구축이 필요한 국내 중소·중견 제조기업으로, 바우처 도입 기업은 향후 스마트공장 고도화 사업의 유력한 후속 고객 후보군이 될 수 있습니다."
