## 조치 필요 항목

### ⚠️ 즉시 수정 — 175ms → ~3,700ms

175ms는 "키워드 룰 단독 경로(<1ms) × 70% 적용 시" 수치이고,  
실제 운영 레이턴시(keep_alive 최적화 후 전체 기준)는 **~3,700ms**가 맞는 수치.

PDF 슬라이드에 오케스트레이터 표가 들어갈 경우 심사위원이 직접 볼 수 있으므로 수정 필요.

**수정 위치 3곳:**

- BM 뼈대 v47 — 7-4절 오케스트레이터 표 `레이턴시: 175ms` 항목
- 풀버전 v3 — 5-1절 오케스트레이터 표 `레이턴시: ~3,700ms` (구버전 비교표 175ms는 유지 가능, 단 "구버전" 명기 필수)
- 발표안 v7 — 3-2절 오케스트레이터 표 `레이턴시 175ms` 항목

**수정 후 표기 기준:**

```
의도분류 레이턴시: ~3,700ms (키워드 룰 <1ms × 70% + EXAONE ~3,700ms × 30%)
```

### ✅ 확인 권장 — 81개 vs 71개 계량기 혼용

두 수치 모두 틀리지 않으나, 슬라이드에서 Honda 학습 데이터를 언급할 때 **81개로 통일** 권장.

- 81개 = 전체 계량기 (전기 71 + 열 9 + 기상 1)
- 71개 = 전기 계량기만 카운트 (풀버전 v3 6-3절 데이터 규모 표에 등장)

질문받으면: *"71개는 전기 계량기만 카운트한 수치이고, 전체는 81개입니다."*
