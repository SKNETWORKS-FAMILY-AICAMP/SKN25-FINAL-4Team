# SKN25 FINAL · 4팀 중간발표 PDF 개선점 브리핑

검토 대상: `SKN25 FINAL · 4팀 — 중간발표.pdf` 12페이지

## 1. 총평

전체 발표 흐름은 안정적입니다. 필요성 → 개요 → 데이터 → EDA → 모델링/이상탐지 → 개발 로드맵 → 남은 과제 → 예상 결과 순서가 자연스럽습니다.

기술 범위도 현재 프로젝트 방향과 맞습니다. PostgreSQL/TimescaleDB, Redis, FastAPI, React, RAG/Agent, 자동 리포팅, 챗봇 인터페이스까지 서비스 연결 범위가 드러납니다.

현재 개선의 핵심은 **시각 자료 가독성, 정보량 압축, 미완성 표시 제거**입니다.

## 2. 우선순위 높은 개선 항목

### 1순위: 7번 슬라이드 placeholder 제거

현재 7번 슬라이드에는 `FIGURE 9 · 확보 예정` 박스가 그대로 보입니다. 이 상태는 미완성 장표처럼 보일 수 있습니다.

개선 방향은 두 가지입니다.

- 상관관계 이미지가 확보되면 `figure 9.png`로 넣고 현재 구조 유지
- 이미지 확보가 어려우면 제목과 구성을 `시계열 분해와 국소 이상 패턴` 중심으로 변경

권장 수정:

- 왼쪽 placeholder 제거
- Figure 3(STL), Figure 4(PF 이상치)를 2분할로 크게 배치
- 상관관계는 발표자가 “추가 분석 예정”으로 설명

### 2순위: 11번 슬라이드 중심 재정렬

11번 제목은 `FEMS 운영지원 프로토타입, 다섯 개의 계층으로`입니다. 그런데 우측에는 요금 추정과 절감 시나리오 그래프가 크게 들어가 있습니다. 최종 산출물의 중심이 서비스 프로토타입인지 비용 분석인지 다소 흐려집니다.

권장 수정:

- 좌측 5계층 구조는 유지
- 우측은 `최종 시연 흐름` 또는 `서비스 통합 아키텍처` 중심으로 변경
- Figure 7, Figure 8은 하나만 크게 쓰거나 8번/부록 성격으로 이동

추천 우측 구성:

1. 운영자가 챗봇에 피크 위험 또는 이상 후보 질의
2. RAG가 문서·데이터 정의·모델 결과 검색
3. 예측/이상탐지 결과 조회
4. Agent가 근거와 함께 응답
5. React 화면 또는 자동 리포트에서 결과 확인

### 3순위: 9번 로드맵 정보량 압축

9번 슬라이드는 프로젝트 범위가 잘 드러납니다. 다만 카드 6개와 하단 역할 카드가 함께 있어 화면 밀도가 높습니다.

권장 수정:

- 6단계 카드는 유지
- 각 단계 bullet은 최대 2개로 제한
- 하단 역할 분화는 3개 레인으로 압축

추천 3개 레인:

| 레인 | 포함 작업 |
|---|---|
| 데이터·모델 | 전처리, DB, 예측, 이상탐지 |
| 서비스 | FastAPI, React, 챗봇 UI |
| LLM Agent | RAG, Orchestrator, Reporting, Critic |

### 4순위: 5번 데이터 구조 이미지 가독성 개선

5번 슬라이드는 필요한 내용이 많습니다. 현재는 데이터 출처 표, 대표 필드 표, Figure 1, Figure 2가 한 장에 함께 들어가 있어 읽기 부담이 있습니다.

권장 수정:

- Figure 1 계량기 구조를 더 크게 배치
- Figure 2 ERD는 전체 이미지를 그대로 쓰기보다 축약 DB 흐름으로 보조
- 한국지역난방공사 데이터는 보조 데이터 후보로 낮은 비중 유지

추천 축약 DB 흐름:

`source_file → full_measurement → cr_measurement_1h / 15min → analysis view`

## 3. 슬라이드별 개선 메모

### 1번 표지

현재 상태는 양호합니다.

개선점:

- 오른쪽 카드 상단 빈 공간에 공장/계량기/데이터 흐름 실루엣을 약하게 추가하면 완성도 상승
- `실증용 proxy` 표현을 작은 캡션으로 추가 가능

우선순위: 낮음

### 3번 프로젝트 필요성

외부 압력 4개 축과 EMS 데이터 활용 흐름이 잘 연결되어 있습니다.

개선점:

- 각 카드 설명문을 더 줄이고 키워드 중심으로 압축
- CBAM/K-ETS/탄소중립은 정책 배경으로만 유지
- 제품별 내재배출량 산정 프로젝트처럼 보이는 표현은 계속 피해야 함

우선순위: 낮음

### 4번 프로젝트 개요

`입력 데이터 → 분석 엔진 → 운영지원` 구조가 명확합니다.

개선점:

- 하단 해석 경계 문장을 3줄 bullet로 압축

추천 압축:

- 계량기·데이터 품질 문제를 먼저 분리
- 잔여 패턴은 설비 점검 후보로 제시
- 고장 확정 표현은 사용하지 않음

우선순위: 중간

### 5번 데이터 구조와 분석 범위

내용은 적절합니다. 이미지와 표가 많아 가독성 조정이 필요합니다.

개선점:

- Figure 1 계량기 구조 확대
- Figure 2 ERD는 축약 도식으로 대체하거나 보조 이미지로 축소
- Honda EMS 데이터와 한국지역난방공사 데이터의 주/보조 관계를 시각적으로 구분

우선순위: 높음

### 6번 EDA — 정상 범위 정의

표 중심 구성이 적절합니다.

개선점:

- 누적 전력량: 단조 증가 또는 reset/gap 분리

우선순위: 중간
