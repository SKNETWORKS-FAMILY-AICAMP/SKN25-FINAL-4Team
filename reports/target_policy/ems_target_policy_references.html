EMS target policy

전력 수요 예측 target 정의 검토

EMS 전력 수요 예측 target은 grid import P와 electricity consumption P를 중심으로 정의한다. 계량기별 시계열, 설비 그룹, 건물, PV·CHP 생산, 열·냉방 계통이 함께 존재하므로 target 정의에는 계량기 구성 변화, 장기 미관측, 중복 계량기, 수입·수출 부호, 설비 증설 시점이 포함된다.

기준 입력: ems.cr_measurement_1h / 15min 우선 target: electricity consumption P / grid import P reduced view: 집계 검산 및 시각화 보조

2. target 정의 이슈

구성 변화

같은 target 이름이 같은 물리 범위를 뜻하지 않을 수 있음

예를 들어 어떤 건물 target이 2018년에는 20개 계량기 합산이고 2023년에는 18개 계량기 합산이면, 모델이 보는 target의 범위가 달라진다.

장기 미관측

결측과 설비·계량기 상태 변화 구분

짧은 gap은 보간 후보가 될 수 있다. 계량기 철거, 운전 시작 전, 장기 중단은 target 구성 변화로 관리한다.

중복 합산

primary와 redundant를 함께 더하면 target이 과대해짐

redundant endpoint는 aggregate에서 제외한다. primary 장기 결측 구간에서 대체값으로 쓸 때는 별도 검증과 flag가 필요하다.

수요와 생산 분리

PV·CHP 생산 P는 target과 feature 역할을 분리

전력 수요 target에는 consumption/import 계열 P를 둔다. PV·CHP는 grid import 설명 feature로 검토할 수 있다.

3. strict와 observed-sum의 위치

여러 component 계량기를 합산할 때 strict와 observed-sum을 함께 산출한다. 두 값은 target 품질 진단 기준으로 사용한다.

기준정의장점한계권장 용도
strict expected component가 모두 관측된 row만 사용 target 범위가 일정하고 성능 평가가 명료함 component가 많거나 장기 미관측이 있으면 row가 크게 줄어듦 benchmark 가능성 평가
observed-sum 관측된 component만 합산하고 count를 함께 기록 row 손실이 작고 운영 데이터 흐름을 볼 수 있음 시기별 component 구성이 바뀌면 target drift 발생 진단, 시각화, 조건부 target 후보
적용 기준: strict coverage와 observed-sum coverage를 함께 계산한 뒤, target별로 고정 패널, coverage threshold, component-set versioning 적용 여부를 결정한다.

4. 선행연구 기반 대안

Fixed panel

1안정 component set 고정

전체 기간 또는 train/validation/test에서 안정적으로 존재하는 component만 골라 target을 구성한다. 패널 데이터와 계량기 기반 예측에 적용하기 쉽다.

적용 예: H2 건물 target에서 전 기간 공통으로 안정적인 18개 meter만 합산한 H2_fixed_panel_P를 별도 target으로 정의한다.

Coverage threshold

2최소 coverage 기준

모든 component를 요구하지 않고 최소 관측률 또는 최소 부하 기여율을 만족하는 row만 사용한다.

component 개수보다 train 기준 평균 부하 share를 우선한다. 작은 meter 결측과 큰 transformer 결측의 영향이 다르다.

Component-set versioning

3구성 변화 구간 분리

component 구성이 바뀌는 시점에 component_set_id를 부여한다. 설비 증설, 계량기 교체, 계량 범위 변경을 target metadata로 남긴다.

적용 예: grid_transformer_v1, grid_transformer_v2. version이 다른 구간의 성능은 같은 표에서 직접 비교하지 않는다.

Redundancy substitution

4primary 결측 시 redundant 대체

primary와 redundant를 동시에 합산하지 않는다. primary가 장기 결측이고 redundant가 동일 물리량을 안정적으로 측정한다고 검증된 경우에만 대체한다.

필수 기록: substitution_flag, 대체 시작·종료 시점, primary-redundant scale 차이, sign 차이.

Bottom-up forecasting

5개별 meter 예측 후 합산

안정적인 meter 또는 group별 예측을 만든 뒤 상위 level로 합산한다.

개별 meter 품질을 분리해 처리할 수 있고, group/building/total 예측의 오차 원인을 추적하기 쉽다.

Hierarchical reconciliation

6계층 일관성 보정

meter, group, building, total 예측값이 합산 구조를 만족하도록 조정한다. Hyndman 계열의 grouped time series, MinT reconciliation 문헌과 연결된다.

전제 조건: 계층 구조가 명확해야 하고, 같은 meter가 여러 target에 중복 반영되지 않아야 한다.

Mask-aware imputation

7결측 mask를 보존한 보간

짧은 산발 결측에는 seasonal interpolation, state-space model, GRU-D, BRITS, SAITS 계열 방법을 검토할 수 있다.

장기 미관측, 운전 시작 전, 계량기 철거, 설비 구성 변화는 보간 대상으로 두지 않는다. target 복원값으로 test 성능을 평가하면 결과 해석이 흐려진다.

Physics balance

8전력 balance 검산

grid import, PV, CHP, consumption aggregate 간 관계를 이용해 sign 오류, component 누락, export 구간을 점검한다.

grid import, net grid, gross load는 서로 다른 물리량이다. target 이름에 물리 의미를 명시해야 한다.

5. target policy 후보

정책정의적용 조건예상 사용처
STRICT_BENCHMARK 모든 component가 관측된 row만 학습·평가에 사용 train/validation/test에서 strict coverage가 충분함 안정적인 설비 group target
FIXED_PANEL_BENCHMARK 공통 안정 component set을 고정해 target 구성 일부 component가 장기 미관측이나 제외 후 target 의미가 유지됨 H2, all_consumption의 보수적 대안
COVERAGE_THRESHOLD_TARGET coverage 또는 load-share 기준을 만족하는 row만 사용 missing component의 부하 기여율이 제한적임 grid_import_P, 일부 group aggregate
VERSIONED_TARGET component set 변화 시 target version을 분리 설비·계량기 구성이 특정 시점에서 바뀜 grid_transformer, H2, all_consumption
OBSERVED_SUM_DIAGNOSTIC 관측 component 합산을 진단과 시각화에 사용 component_count와 load-share를 함께 제공함 coverage 점검, 흐름 파악, 대시보드
EXCLUDE target 목적과 맞지 않거나 품질 기준 미달 production, thermal, weather, redundant 동시합산, 품질 불충분 target 제외. feature 활용은 별도 검토

7. EMS 적용 우선순위

  1. CR mart 기준 유지: target 검증과 feature baseline은 ems.cr_measurement_1h와 ems.cr_measurement_15min을 기준으로 작성한다.
  2. strict와 observed-sum 동시 산출: 두 기준을 target 품질 진단의 시작점으로 사용한다.
  3. fixed-panel 산출: target별 안정 component set을 찾고, 기존 target명과 별도 이름으로 관리한다.
  4. load-share 기반 threshold 추가: component 개수보다 부하 기여율 기준을 우선 검토한다.
  5. component-set versioning 적용: H2, grid_transformer, all_consumption처럼 구성 변화가 큰 target에 version을 부여한다.
  6. grid_import_P 별도 관리: net grid P, export 구간, import clipping, component coverage를 함께 기록한다.
정책 선택: target별로 STRICT_BENCHMARK, FIXED_PANEL_BENCHMARK, COVERAGE_THRESHOLD_TARGET, VERSIONED_TARGET, OBSERVED_SUM_DIAGNOSTIC를 부여한다. EMS 데이터는 target별 정책 분리가 필요하다.
