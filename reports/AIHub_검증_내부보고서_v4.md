## 1. 검증 목적 및 배경

### 1-1. 목적

TTF-FMS 플랫폼의 핵심 ML 모델(Import P-Max, v84 앙상블)은 독일 Honda R&D Europe EMS 데이터(2018~2024, 6년치, 81개 계량기)를 기반으로 개발됐다. 플랫폼의 실제 타깃은 국내 중소 제조기업이므로, 동일한 모델 구조가 국내 제조설비 데이터에서도 유효하게 작동하는지 외부 검증이 필요했다.

본 검증의 목적은 다음 두 가지다.

1. **구조 전이 가능성 확인**: Honda 데이터로 설계된 모델 구조(피처 엔지니어링, 앙상블 방식, 잔차 타겟 등)가 국내 제조설비 데이터에도 통하는지 확인 (현재 검증 범위: AI Hub 펌프/일반모터 73개 설비)
2. **재학습 필요성 정량화**: Honda 가중치 그대로 사용 vs 국내 데이터로 재학습했을 때 성능 차이를 수치로 확인하고, 고객사 온보딩 시 재학습 설계의 근거 확보

### 1-2. 검증 데이터

- **출처**: AI Hub 전력 설비 에너지 품질 데이터셋 (#149)
- **설비 유형**: 펌프/일반모터
- **설비 수**: 73개
- **라벨**: 정상/주의/경고 (역률 기준 SOH 진단)
- **Training 기간**: 설비당 약 27일치 (648시간, 1시간 리샘플링 기준)
- **Validation 기간**: 설비당 약 3~6일치 (72~144시간)
- **데이터 형식**: JSON (ITEM_NAME/ITEM_VALUE/TIMESTAMP/LABEL_NAME 구조), 분 단위 raw → 1시간 리샘플링 후 사용

### 1-3. 검증 전략

```
Honda 학습 완료 모델
        ↓
① Honda 가중치 그대로 → AI Hub 데이터 추론
        ↓

```

## 2. Import P-Max 전이 검증

### 2-1. 모델 개요

Import P-Max는 공장 전체 수입 전력(Import) 피크 예측 모델이다.

- **구조**: LightGBM×2 + XGBoost + CatBoost (4개 모델 가중 앙상블)
- **타겟**: P_max (15분 단위 최대 전력, 절대값)
- **입력**: 최근 24시간 15분 단위 시계열 (96 시점), 22개 피처
- **정규화**: 없음 (raw 값 그대로 학습) — `training.py` 코드 확인
- **Honda 성능**: persistence 대비 RMSE 개선 11~18%, 추론 70,660건 실패 0건
- **Honda 분할**: 고정 날짜 분할 (train 2018~2021, val 2022, test 2023)

### 2-2. 실험 설계 (7종)

Honda 가중치 그대로 적용 시 스케일 차이 문제가 예상됐다. Honda 계량기는 수만 kW 단위, AI Hub 펌프/모터는 수백~수천 W 단위로 약 10~100배 스케일 차이가 있다. 이를 확인하고 해결책을 찾기 위해 7가지 실험을 순차적으로 진행했다.

### 2-4. 결과 분석

**Honda 가중치 그대로 (실험 1~5)**

모든 구현 방식에서 성능이 무너졌다. 중앙값 RMSE 개선율이 -376% ~ -1,147%로 persistence보다 수백 배 나쁜 결과다. 원인은 스케일 불일치다. Import P-Max는 정규화 없이 raw 절대값으로 학습했기 때문에(`training.py` 코드 확인), Honda 계량기 스케일(수만 kW)로 학습된 가중치가 AI Hub 스케일(수백~수천 W)에서 전혀 작동하지 못한다.

StandardScaler/MinMaxScaler를 전처리로 추가해도(-424%, -641%) 오히려 더 나빠졌다. 입력은 정규화됐지만 출력(예측값)이 Honda 스케일로 나와서 AI Hub 실측값과 비교가 불가능한 구조적 문제다.

**AI Hub 재학습 (실험 6~7)**

Validation 3~6일치 재학습(실험 6)은 50% 개선, RMSE 개선율 -0.4%로 거의 효과가 없었다. 데이터가 너무 짧아서 패턴을 제대로 학습하지 못한 것이다.

Training 27일치 재학습(실험 7)에서 유효 설비 85%에서 개선, 중앙값 RMSE 개선율 +17.5%가 나왔다. Honda 결과(11~18%)의 범위 내에 위치한다. 구조가 동일하면 충분한 데이터로 재학습 시 Honda와 유사한 성능이 나온다는 근거다.

## 3. v84 앙상블 예측 전이 검증

### 3-1. 모델 개요

v84는 Honda EMS 데이터 전체로 학습한 1시간 단위 전력 수요 예측 앙상블 모델이다.

- **구조**: LSTM×6 + CatBoost + LightGBM + Ridge + Seasonal Naive → median 앙상블 → shrunk hour bias correction
- **타겟**: 잔차 P(t+h) - P(t-1) (변화량 예측 후 anchor 복원)
- **입력 정규화**: input_scaler + target_scaler 내장 (StandardScaler)
- **계량기별 개인화**: 45개 계량기 각각 별도 학습
- **horizon**: 1h / 3h
- **Honda 성능**: 1h 평균 MAE 2,824W, beats_persistence 27/45
- **Honda 분할**: 데이터 길이 기반 동적 분할 (`preprocessing.py` `determine_split_bounds` 함수)
  - Honda 6년치: 고정 날짜 분할 (train 2018~2021, val 2022, test 2023)
  - 단기 데이터: 비율 분할 (train 4/6, val 1/6, test 1/6)

Import P-Max와 달리 v84는 잔차 타겟 + 내장 정규화 구조를 가지기 때문에 스케일 불일치에 상대적으로 강건하다.

### 3-2. 실험 설계 (5종)

| 실험 1 | Honda 가중치 그대로 (자체 스크립트) | proxy H1.Z10 artifact → AI Hub Training 추론, 직접 구현 | `aihub_v84_validation.py` | `aihub_v84_validation_per_device.csv` |

### 3-4. 결과 분석

**실험 1 vs 실험 2: 구현 방식의 중요성**

동일한 Honda 가중치를 사용했음에도 자체 스크립트(19%, -84.1%)와 inference.py(59%, +3.9%) 결과가 크게 달랐다. 자체 스크립트는 feature engineering, scaler 적용, 잔차 복원 등 v84 추론 파이프라인의 세부 구현을 재현하지 못한 것이 원인이다. inference.py의 predict_meter를 직접 호출해야 정확한 결과가 나온다.

**Honda 가중치 그대로도 59% 개선이 나온 이유**

Import P-Max(12%)와 달리 v84는 두 가지 구조적 특성 덕분에 가중치 그대로도 절반 이상의 설비에서 통했다.

첫째, **잔차 타겟** 구조다. P(t+h) 절대값이 아니라 P(t+h) - P(t-1) 변화량을 예측하기 때문에, Honda(수만 kW)와 AI Hub(수백~수천 W)의 절대값 스케일 차이가 예측에 미치는 영향이 줄어든다.

둘째, **input_scaler + target_scaler 내장**이다. 입력과 출력을 모두 정규화하는 구조라서, AI Hub 기기별 스케일이 달라도 스케일러가 어느 정도 보정해준다.

**재학습 계열 스킵 다수 발생 원인**

`preprocessing.py`의 `determine_split_bounds` 함수에서 단기 데이터(Honda 6년치 범위 미달)는 비율 분할(4/6, 1/6, 1/6)을 적용한다. 27일치(648시간) 기준으로 val/test 구간이 각각 108시간(4.5일)이다. bundle_168 LSTM은 168시간 윈도우가 필요하므로 108시간 구간에서 윈도우 0개 생성 → 스킵 발생. 코드로 확인됨.

bundle_168 풀 재학습을 위한 최소 데이터 요구량: val/test 각각 168시간 이상 필요 → span × 1/6 ≥ 168시간 → span ≥ 1,008시간 = **최소 42일치** 필요. (`preprocessing.py` 코드 기반 계산)

**재학습이 가중치 그대로보다 낮은 이유**

재학습(39%) < 가중치 그대로(59%)라는 역전 결과는 재학습이 잘못된 게 아니라 재학습이 제대로 안 된 것이다. bundle_168 LSTM이 4.5일 val/test 구간에서 정상 학습이 안 되는 구조적 한계다. 충분한 데이터(최소 42일치 이상)로 재학습 시 59%보다 높아질 것으로 판단하나, 수치 증명은 미완료다.

**재학습 결과가 낮게 나온 것은 모델 구조의 한계가 아니라 AI Hub 데이터 기간(27일)이 bundle_168 LSTM이 요구하는 최소 기간(42일)에 미달했기 때문이다.**

### 3-5. 소결

- Honda 가중치 그대로 + inference.py 사용 시 56개 설비 중 59% 개선 → **구조 전이 가능성 확인**
- 잔차 타겟 + 내장 정규화 구조가 스케일 차이에 강건한 설계임을 실험으로 확인
- 재학습 계열은 데이터 기간 부족(27일치 < 42일치)으로 완전한 검증 불가 → 장기 데이터 확보 시 추가 검증 필요
- 모든 수치 원본 CSV와 일치 확인 완료

## 4. v84 이상탐지 전이 검증

### 4-1. 이상탐지 구조 개요

v84 이상탐지는 예측 잔차 기반 threshold 구조다.

```
v84 예측 → 예측값 vs Training 기준 시간대별 2~98 percentile threshold 비교
→ 초과 시 경보 발생 (warning_flag = True)
→ anomaly_agent + 센서값 + ANOMALY_DOMAIN_PROMPT → LLM → 운영 유형 해석
(PowerSpike / COPDrop / NightConsumption / CHPOutage / PVNightNonZero)
```

이상탐지 성능 평가는 Honda와 동일한 4분류 방식을 사용했다.

| 분류 | 의미 |
|------|------|
| po_ao | 이상 구간 & 경보 발생 (탐지 성공) |
| po_ai | 정상 구간 & 경보 발생 (오탐) |
| pi_ao | 이상 구간 & 경보 미발생 (미탐) |
| pi_ai | 정상 구간 & 경보 미발생 (정상 처리) |

※ Honda 데이터에는 정답 레이블이 없어 actual P가 val 기준 시간대별 정상 범위(2~98 percentile) 밖에 있으면 이상으로 정의하는 통계적 proxy를 사용했다. AI Hub 검증도 동일한 방식을 적용했다.

### 4-2. 실험 설계 (2종)

**실험 A: Honda 가중치 그대로**
- proxy artifact: H1.Z10 (Honda 계량기)
- AI Hub 기기별 threshold: Training actual P 시간대별 2~98 percentile 계산 후 직접 주입
- 추론: inference.py predict_meter 호출
- 대상: AI Hub 73개 설비 중 유효 58개
- 스크립트: `aihub_v84_anomaly_validation.py`
- 출력: `aihub_v84_anomaly_per_device.csv`

**실험 B: AI Hub 재학습 후**
- Training 데이터로 설비별 재학습 (LSTM v3 168h 윈도우 제외, v1/v2/v4/v6/v7 24h 윈도우 기반)
- Training + Validation 이어붙여서 diff_lag168 피처 충당, Validation 구간에서만 테스트
- 동일한 threshold 방식 적용 (Training actual P 기준 시간대별 2~98 percentile, floor=-50W)
- Honda와 동일한 잔차 타겟, median 앙상블, shrunk hour bias correction 구조 재현
- 대상: AI Hub 73개 설비 중 유효 65개 (전체 저장 69개, n_test_windows=0인 4개 제외)
- 스크립트: `aihub_v84_anomaly_retrain_with_lstm.py`
- 출력: `aihub_v84_anomaly_retrain_with_lstm.csv`

**v3 LSTM 제외 이유**: bundle_168(168h 윈도우)은 Validation 72시간 구간에서 윈도우 0개 생성. 재학습 자체가 불가능해서 24h 윈도우 기반 경량 구조(v1/v2/v4/v6/v7)로 대체.

**검증 방식 타당성**: 실험 B는 Honda 이상탐지 파이프라인의 핵심 구조(잔차 타겟, median 앙상블, shrunk hour bias correction, Training actual P 기준 threshold, floor=-50W)를 코드로 동일하게 재현했다. 코드 확인 완료.

### 4-3. 실험 결과

| 지표 | Honda (3h, 2023) | 실험 A: 가중치 그대로 | 실험 B: 재학습 후 |
|------|:---:|:---:|:---:|
| 경보율 | 17.79% | 37.53% | **20.04%** |
| po_ao율 (탐지 성공) | 9.79% | 6.42% | **8.27%** |
| po_ai율 (오탐) | 7.92% | 31.10% | **11.77%** |
| pi_ao율 (미탐) | 3.75% | 8.86% | 8.71% |
| 유효 설비 수 | 63개 | 58개 | 65개 |

※ CSV 기반 수치 검증 완료.

### 4-4. 결과 분석

**실험 A: Honda 가중치 그대로**

경보율 37.53%로 Honda(17.79%)의 2배 이상이다. 오탐(po_ai)이 31.10%로 압도적으로 높다. Honda 패턴으로 학습된 v84가 AI Hub 기기의 정상 패턴을 제대로 예측하지 못해서, 실제로는 정상인 구간에서도 예측 잔차가 커져 경보가 과다 발생하는 것이다.

**실험 B: AI Hub 재학습 후**

재학습 후 경보율 20.04%로 Honda(17.79%) 방향으로 유의미하게 개선됐다. 오탐(po_ai)이 31.10% → 11.77%로 19.33%p 대폭 감소했다. AI Hub 기기 패턴을 학습한 덕분에 정상 구간 예측 정확도가 높아져 오탐이 줄어든 것이다.

po_ao율(탐지 성공)은 6.42% → 8.27%로 오히려 개선됐다. 이상 구간에서 더 정확하게 잔차를 포착하는 결과다.

pi_ao율(미탐)은 8.86% → 8.71%로 거의 변화 없다. 미탐은 threshold 설계와 관련이 깊은데, Training actual P 기반 threshold가 두 실험 모두 동일하게 적용됐기 때문이다.

**구조 해석**

재학습 후 결과가 Honda 운영 수준 방향으로 유의미하게 개선됐다는 것은, v84 이상탐지 파이프라인 구조(잔차 기반 + 시간대별 threshold)가 국내 제조설비 데이터에서도 유효하게 작동함을 의미한다. 고객사 데이터로 재학습하면 도메인 적응이 가능한 구조다.

### 4-5. 소결

- Honda 가중치 그대로: 오탐 31.10%로 국내 데이터 미적응 상태
- 재학습 후: 경보율 20.04%, 오탐 31.10% → 11.77%(-19.33%p) → **도메인 적응 확인**
- 이상탐지 파이프라인 구조(잔차 기반 + 시간대별 threshold)의 전이 가능성 확인
- 모든 수치 원본 CSV와 일치 확인 완료

## 6. 한계 및 향후 과제

### 6-1. 데이터 기간 부족

AI Hub Training 27일치는 v84 풀 재학습에 부족하다. `preprocessing.py` `determine_split_bounds` 코드 분석 결과, bundle_168 LSTM(168시간 윈도우) 풀 재학습을 위한 최소 데이터 요구량은 **42일치**다 (val/test 각각 168시간 이상 필요, span × 1/6 ≥ 168시간). 현재 v84 이상탐지 재학습 결과(실험 B)는 v3 LSTM을 제외한 경량 구조 기반으로, 풀 v84 재학습 결과가 아님을 명시한다.

실제 고객사 데이터가 6개월 이상 축적되면 풀 v84 재학습이 가능하고, 현재보다 높은 성능이 기대된다.

### 6-2. 라벨 기반 이상탐지 검증 불가

AI Hub 라벨(정상/주의/경고)은 역률 기반 SOH 진단 기준이다. v84 이상탐지가 잡으려는 전력 패턴 이상과 정의 기준이 다르기 때문에, AI Hub 라벨로 recall/precision 등 정답 레이블 기반 지표를 계산하는 것은 의미가 없다.

이상탐지 성능은 Honda와 동일한 통계적 proxy(actual P vs 시간대별 2~98 percentile threshold) 기준으로만 평가됐다.

### 6-3. 단일 설비 유형 검증

현재 검증은 AI Hub 펌프/일반모터 73개 설비만 대상이다. 압축기, 열교환기, 공조기 등 다른 설비 유형에서의 검증은 미완료다.

### 6-4. 실험 1 CSV 손상

Import P-Max 실험 1(`aihub_pmax_honda_inference_per_device.csv`) 파일이 이어쓰기 중 손상되어 9개 설비만 유효하게 읽힌다. 실험 1은 "Honda 가중치 그대로 Validation 추론 시 성능 붕괴"라는 방향성 확인 목적이므로 발표 방어에 영향 없다.

> Honda 데이터로 개발한 모델을 AI Hub 국내 제조설비 데이터에 적용해본 결과, Import P-Max는 재학습 후 Honda와 유사한 성능 범위를 보였고, v84는 Honda 가중치 그대로도 절반 이상 설비에서 개선 효과를 보였으며, 이상탐지 역시 재학습 후 오탐율이 크게 감소했습니다. 따라서 고객사 데이터로 재학습한다는 전제하에 모델 구조의 전이 가능성을 확인했습니다.

### 8-4. 예상 질문 답변 준비

**Q. "59%가 무슨 뜻입니까?"**
> "56개 유효 설비 중 33개 설비에서 Persistence 대비 RMSE가 개선됐다는 의미입니다."

**Q. "Honda 데이터라 국내 제조업에 안 통하는 거 아닙니까?"**
> "AI Hub 국내 펌프/모터 73개 설비로 외부 검증을 수행했습니다. Import P-Max는 재학습 후 Honda 결과 범위(11~18%) 내 17.5% 개선이 나왔고, v84는 Honda 가중치 그대로도 59% 설비에서 개선됐습니다."

**Q. "재학습했는데 왜 Honda 가중치보다 성능이 낮습니까?"**
> "재학습이 잘못된 게 아니라 AI Hub 데이터 기간(27일)이 bundle_168 LSTM이 요구하는 최소 기간(42일)에 미달해서 재학습이 제대로 안 된 겁니다. 구조의 문제가 아닙니다."

**Q. "이상탐지가 실제로 PowerSpike 같은 유형을 분류할 수 있습니까?"**
> "v84 예측 기반 경보 구조(warning_flag)가 국내 설비에서도 작동함을 확인했습니다. PowerSpike 등 운영 유형 해석은 anomaly_agent와 LLM이 담당하는 별도 레이어입니다."
